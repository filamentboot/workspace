<objective>
在主包 FilamentAdminServiceProvider 的 registerPolicies() 中，将现有超管 Gate::before 回调扩展为合并回调：在超管放行判定**之前**插入演示拒绝分支，对演示用户的写类 ability 返回 `false`（直接拒绝、短路 Gate 链路），读类 ability 返回 `null`（放行后续判定）。新增 isDemoUser / isWriteAbility 私有方法。这是对 D-05-05「拦 HTTP DELETE 中间件」的纠偏实现（Filament 5 删除走 Livewire AJAX，HTTP 动词中间件失效——见 RESEARCH §3），改用 Gate::before 覆盖所有 ability，符合 DEMO-03 的更广拦截口径（create/update/delete + 批量，Admin/Role/Permission/Department/Setting）。

Purpose: DEMO-03 高危操作屏蔽——演示环境不可执行写/删操作。最大技术难点是 [BLOCKING] 的超管顺序：现有 ServiceProvider 超管放行返回 true 会短路一切，必须让演示拒绝先执行。

Output: 修改后的 registerPolicies()（合并 Gate::before）+ isDemoUser/isWriteAbility 方法 + DemoModeGuardTest（覆盖屏蔽、读放行、超管顺序）。
</objective>
