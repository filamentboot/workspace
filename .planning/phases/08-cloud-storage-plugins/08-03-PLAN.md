<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| 上传者（浏览器）→ 应用 | 上传文件名/扩展名/Content-Type 头均为不可信输入 |
| 应用 → 存储磁盘 | 校验通过的文件才写入磁盘（含本地 / OSS / COS） |
| 后台超管 → UploadSettingsPage | default_disk 选择影响 medialibrary 落盘位置 |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-03 | Tampering | 上传可执行/脚本文件（.php/.exe/.sh） | mitigate | UploadValidator 扩展名黑名单 + finfo 服务端真实 MIME 校验，并通过 FileUpload::configureUsing 全局接入实际上传流程（Task 3 test_upload_validator_is_wired_into_fileupload 断言非法文件被拒） |
| T-08-05 | Spoofing | 伪造 HTTP Content-Type 头绕过 MIME 校验 | mitigate | 使用 `new \finfo(FILEINFO_MIME_TYPE)` 读取文件真实内容判定 MIME，不信任 `getClientMimeType`（Task 1 test_rejects_mime_mismatch 断言） |
| T-08-06 | Denial of Service | 上传超大文件耗尽磁盘/带宽 | mitigate | 文件大小 ≤ UploadSettings.max_file_size，超限抛异常（Task 1 test_rejects_oversize_file 断言） |
| T-08-07 | Information Disclosure | 未知扩展名/MIME 误放行 | mitigate | MIME 映射对未知扩展名保守处理（默认拒绝而非放行） |
| T-08-11 | Tampering | medialibrary 落盘磁盘与 UploadSettings 不一致（切换后未生效） | mitigate | ServiceProvider 启动钩子 + SettingsPage 保存钩子双重同步 media-library.disk_name = UploadSettings.default_disk（Task 2/3 断言，D-08-07） |
</threat_model>
