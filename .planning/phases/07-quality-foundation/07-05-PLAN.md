## 关键约束（来自 CONTEXT / ROADMAP / 现状核查）

- **D-02 范围语义：** 普通管理员看「本部门 + 所有子部门（子树）」。管理员的「本部门」= `AdminUser.department_id`（model 第 119 行有 department() 关系、@property department_id）。用 `DepartmentTree::getSelfAndDescendantIds(Department)`（service 第 45-51 行，已存在「本部门 + 子树」一站式方法）解析可见部门 id 集合，`whereIn('id', $ids)` 过滤。
- **D-01 二元范式（范本）：** AdminUserResource::getEloquentQuery() 第 170-191 行 / LoginLogResource 第 146-162 行：`$user = auth('admin')->user()`；非 AdminUser → `whereRaw('1 = 0')`；`hasRole(config('filament-admin.super_admin_role'))` → 直接返回全量；否则加 where 限制。DepartmentResource 照此扩展。
- **现状 getEloquentQuery（第 140-147 行）：** 仅 `with(['parent','leader'])` + `withoutGlobalScopes([SoftDeletingScope])`，无数据范围。需在其上叠加数据范围分支，保留 with/withoutGlobalScopes。
- **边界：管理员无 department_id（null）时** 普通管理员看不到任何部门（whereRaw 1=0 或空集合）——按「受限」语义安全收敛；记入测试用例。
- **D-03 纠偏：** 本 plan **不动 MenuResource::getEloquentQuery()**（与 ROADMAP 原文「菜单列表也过滤」相左——菜单全局无归属，过滤无语义，仅靠 view_menu 权限点）。此为对 ROADMAP 的纠偏，记入 SUMMARY。
