## 关键约束（来自 CONTEXT / ROADMAP / 现状核查）

- **D-05 机制：** 用 **Filament panel 中间件**（注册到 AdminPanelProvider 的 `->middleware([...])` 或 `->authMiddleware([...])`，与 panel 路由模型一致），**不建独立全局 HTTP 中间件**。新建 `FilamentAdmin\Http\Middleware\EnsureTwoFactorEnabled`（包内 src/Http/Middleware/，确认目录是否存在，不存在则创建）。authMiddleware 仅在认证后路由生效，适合「已登录但未开 2FA」拦截——优先放 `->authMiddleware([Authenticate::class, EnsureTwoFactorEnabled::class])`（在 Authenticate 之后，确保已有用户）。
- **D-04 超管也强制：** 不对 super_admin_role 豁免。判定仅看 force_2fa 与该用户是否已启用 2FA。
- **D-06 放行清单（务必，防锁死）：** 强制拦截时放行——登出路由、2FA 设置/管理页、个人资料页（Profile）。中间件需识别当前请求是否命中这些放行路由（用 `$request->routeIs(...)` 模式匹配 Filament 的 logout / two-factor / profile 路由名，或对比当前 path 与这些页面 URL）。read_first 必须确认这些路由的实际名称/路径（TwoFactorAuthenticationPlugin 提供的 2FA 设置页路由、Filament logout 路由、Profile 页路由 `->profile(Profile::class)`）。
- **「是否已启用 2FA」判定：** AdminUser use `TwoFactorAuthenticatable`（CLAUDE.md 架构表载明），通常以 `two_factor_secret` 非空（且 stephenjude/filament-two-factor-authentication 的确认态字段）判定已启用。read_first 确认该插件判定「已启用」的准确字段/方法（如 `$user->two_factor_secret` 非空 / 插件提供的 `hasEnabledTwoFactor()` 之类），以其为准，避免误判。
- 未启用 2FA 且 force_2fa=true 且非放行路由 → redirect 到 2FA 设置页（带提示）。已启用或 force_2fa=false → next($request)。
- **本任务改 AdminPanelProvider.php——与 07-04 同文件，依赖 wave 串行（本 Wave 4 在 07-04 Wave 3 后）。**

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| 已登录管理员 → 后台页面 | force_2fa 开启时未开 2FA 者不应访问业务页 |
| 强制拦截 → 放行清单 | 必须保证设置页/登出可达，否则账号被永久锁死 |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-15 | Elevation of Privilege | 未开 2FA 即访问后台（含超管） | mitigate | EnsureTwoFactorEnabled 按 force_2fa 拦截，超管不豁免（D-04）；Force2faEnforcementTest 用例 A/D 覆盖 |
| T-07-16 | Denial of Service | 强制拦截把账号锁死 | mitigate | 放行清单（登出/2FA设置/个人资料）经 routeIs 匹配，用例 B 验证设置页/登出可达（D-06） |
| T-07-17 | Spoofing | 绕过中间件直达业务页 | mitigate | 注册在 authMiddleware（Authenticate 之后），覆盖所有 panel 认证后路由；放行清单为白名单非黑名单 |
