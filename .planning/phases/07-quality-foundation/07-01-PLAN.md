## 关键约束（来自 CONTEXT / ROADMAP / 现状核查）

- **FIX-01 根节点现状：** `AdminNavigationBuilder::build()` 第 32 行硬编码 `->where('parent_id', 0)`；而迁移 `2026_06_02_000002_migrate_menus_parent_id_for_tree` 将 menus.parent_id 设为 NOT NULL DEFAULT 0（filament-tree 用整数 0 标记根，不能用 NULL），`Menu::defaultParentKey()` 返回 `0`。
- **关于「parent_id=null」的纠偏：** ROADMAP 原文要求把根判定改成 `null`，但这与 filament-tree 迁移设计（根=0、NOT NULL）直接冲突，强行改 null 会破坏现有树结构。**本 plan 采用安全解读：让 build() 同时兼容 0 与 null 两种根标识**（用 `Menu::defaultParentKey()` 作为根判定来源，并对 null 也放行），不改迁移、不改 `defaultParentKey()` 返回值。此为对 ROADMAP 原文的实现层纠偏，记入 SUMMARY 偏差说明。
- **FIX-01 第二点：** 当前 build() 在 `if ($items === []) continue;` 处会跳过「无子菜单的顶级组」。需求要求：顶级组自身若可解析为可点击导航项（有 route_name/url 且权限放行），即使无子项也应作为可点击导航项显示，而非被跳过。
- **FIX-04：** 删除 LoginLogResource 第 43-64 行冗余 `form()` 方法；`canCreate()` 返回 false 必须保留（登录日志只读）。
- **FIX-07：** AdminUserResource 第 103 行 `->visible(fn () => auth('admin')->user()?->can('assign_role_admin_user') ?? false)` 改为调用已有 `AdminUserPolicy::assignRole(Authenticatable, Model)`。注意 `assignRole` 签名需 `$user` 与 `$model` 两参（见 AdminUserPolicy 第 27-30 行），表单场景用 `auth('admin')->user()->can('assignRole', AdminUser::class)`（Gate 形式，model 传类名即可触发 Policy 方法）等价表达，确保最终落到 `AdminUserPolicy::assignRole`。
