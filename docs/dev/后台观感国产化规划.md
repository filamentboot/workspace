# 后台观感国产化规划（字号 / 间距 / 密度）

> 状态：**已实施，本文保留为实施前的调研记录**。最终改了什么、怎么继续改，见
> [后台样式改造说明.md](后台样式改造说明.md)。
>
> ⚠️ **本文第 3 节 P0 第 1 项「根字号 16px → 14px」的结论是错的**，实施阶段被实测推翻：
> `--text-sm = .875rem`，Filament 正文全部走 `text-sm`，在 16px 根字号下已是 14px
> （即 Ant `fontSize` / Element `$font-size-base`）。压根字号会让正文变成 12.25px。
> 该项已废弃，未实施；下方 4.3 节关于 `--spacing` 连带缩放的风险讨论随之作废。
> 背景：现有覆盖层 `packages/filamentboot/resources/dist/filamentboot-theme.css`（122 行）已做了圆角、表格行高、边框、中文字体，但实际观感与国内后台仍有明显距离。本文定位剩余缺口并给出全局化、可下游覆盖的实施方案。

---

## 1. 调研：国内主流后台的规范数值

取两条国内实际占有率最高的路线作为基准。数值全部来自各设计体系的 token 源文件，非二手转述。

### 1.1 Ant Design 5（Ant Design Pro 路线）

来源：`ant-design/components/theme/themes/seed.ts`、`shared/genSizeMapToken.ts`、`shared/genFontSizes.ts`

| Token | 值 |
|---|---|
| `fontSize`（基准字号） | **14** |
| `sizeUnit` / `sizeStep` | 4 / 4 |
| 间距阶梯 `sizeXXS…sizeXXL` | **4 / 8 / 12 / 16 / 20 / 24 / 32 / 48** |
| `borderRadius` | **6**（LG 8 / SM 4 / XS 2） |
| `controlHeight`（控件高度） | **32**（SM 24 / LG 40） |
| `lineWidth` | 1 |
| 字号阶梯 | **12 / 14 / 16 / 20 / 24 / 30 / 38** |
| 行高公式 | `lineHeight = (fontSize + 8) / fontSize` → 14px 对应 **1.571（22px）** |
| 标题字号 | H1 38 / H2 30 / H3 24 / H4 **20** / H5 **16** |
| `colorPrimary` | `#1677ff` |
| `colorSuccess / Warning / Error` | `#52c41a` / `#faad14` / `#ff4d4f` |

> 字号阶梯按 `genFontSizes.ts` 的公式 `base × e^(i/5)` 取偶数复算得出（base=14 → 12/14/16/20/24/30/38），与 Ant 文档公布的 Heading 值一致。

### 1.2 Element Plus（若依 RuoYi / vue-element-admin 路线）

来源：`element-plus/packages/theme-chalk/src/common/var.scss`

| 变量 | 值 |
|---|---|
| 字号 | base **14** / small 13 / extra-small 12 / medium 16 / large 18 |
| 控件高度 | large 40 / **default 32** / small 24 |
| 圆角 | base **4** / small 2 |
| 表格行 padding | large `12px 0` / **default `8px 0`** / small `4px 0` |
| 表格单元格 padding | large `0 16px` / **default `0 12px`** / small `0 8px` |
| 边框色 | **`#dcdfe6`** / light `#e4e7ed` / lighter `#ebeef5` |
| 菜单项高度 | 56（Element 侧栏偏高，不建议照搬） |

### 1.3 两条路线的共识

国内后台的"紧凑感"来自四个数字高度一致：**基准字号 14px、控件高度 32px、圆角 4-6px、间距 4 的倍数（8/12/16/24）**；外加**灰底白卡 + 明显边框**的层次。

## 2. 现状实测（Chromium 1600×1000，已登录，含现有覆盖层）

用 `getComputedStyle` 实测，非读源码推断。

### 2.1 全局

| 项 | 实测值 | 国内基准 | 差距 |
|---|---|---|---|
| 根字号 `html` | **16px** | 14px | ⚠️ **全站放大 14%，是"间距偏大"的总开关** |
| 行高 | 24px（1.5） | 22px（1.571 @14px） | 偏紧（CJK 更需要行高） |
| `body` 背景 | `oklch(0.985 0 0)` ≈ `#fafafa` | `#f0f2f5` / `#f5f5f5` | ⚠️ 灰底几乎不可见，卡片层次丢失 |
| 卡片边框 | 1px `oklch(0.92)` ≈ `#e5e5e6` | `#dcdfe6` / `#d9d9d9` | 偏浅 |
| 卡片圆角 | 6px | 4-6px | ✅ 已对齐 |
| 主内容区左右留白 | 16px | 24px（Ant Pro） | 反而偏窄 |
| 字体栈 | 中文系统字体栈 | — | ✅ 已对齐 |
| 主色 | `#1677ff` | `#1677ff` | ✅ 已完全一致 |

### 2.2 框架与侧边栏

| 项 | 实测值 | 国内基准 | 差距 |
|---|---|---|---|
| 侧栏宽度 | **320px**（Filament 默认 `20rem`） | 208-256（Ant Pro）/ 210（若依） | ⚠️ **宽 25-54%** |
| 顶栏高度 | 64px | 48-56 | 偏高 |
| 侧栏项高度 | 40px | 40 | ✅ 已对齐 |
| 侧栏项字号 | 14px / 500 | 14px | ✅ |
| 分组图标尺寸 | **24px** | 14-16 | 偏大 |
| 页面标题 | **30px / 700** | 20px / 600（Ant H4） | ⚠️ 大了一号半 |
| 页面头部高度 | 64px | — | 随标题一起收 |

### 2.3 列表页

| 项 | 实测值 | 国内基准 | 差距 |
|---|---|---|---|
| 表头背景 | `#fafafa` | `#fafafa`(Ant) / `#f5f7fa`(Element) | ✅ 覆盖层已生效 |
| 表头字号/字重 | 14px / 600 | 14 / 500-600 | ✅ |
| 表头 padding | `8px 12px 8px 24px` | `0 16px` | 首列左缩进 24px 偏大 |
| 数据行高 | 41px | 40（Element default） | ✅ 已对齐 |
| 单元格 padding | `0 0 0 12px` | `0 12px` | ✅ |
| 工具栏高度 | 61px | — | 可压缩 |

### 2.4 表单页

| 项 | 实测值 | 国内基准 | 说明 |
|---|---|---|---|
| 字段纵向间距 | 24px | Ant Form.Item `marginBottom` = 24 | ✅ **与 Ant 一致，不是问题** |
| 栅格列间距 | 24px | 24 | ✅ |
| 标签字号/字重 | 14px / 400 | 14 / 400 | ✅ |
| 输入框高度 | **36px** | **32px** | ⚠️ 高一档 |
| 按钮高度 | **36px** | **32px** | ⚠️ 高一档 |
| 输入框圆角 | 4px | 4-6 | ✅ |

> **重要结论**：表单的"松"不在间距数值上（24px 与 Ant 默认相同），而在**根字号 16px 把所有 rem 单位撑大了** + **控件高 36 而非 32**。国内后台额外的紧凑感来自 label 左置（horizontal）布局，那是结构改动，见 P2。

## 4. 实施方案

### 4.1 全部落在现有覆盖层，不新增机制

`packages/filamentboot/resources/dist/filamentboot-theme.css` 的现有机制是正确的，直接扩充：

- **无 `@layer`** → 按 CSS 级联恒胜 Filament 的 `@layer components/utilities`，不需要 `!important`，不与 Filament 升级耦合；
- 经 `FilamentAsset::register()` 注入，下游 `composer require` 后零配置生效，无需改 `vite.config.js` 或 `npm run build`；
- `FILAMENTBOOT_THEME=false` 可整层关闭。

唯一例外是**侧栏宽度**：Filament 5 提供官方 API `->sidebarWidth()` / `->collapsedSidebarWidth()`（`HasSidebar.php`，默认 `20rem`），走 API 而不是 CSS 覆盖。这需要在 `AdminPanelProvider` 改一行，且要在 README / 升级说明里告知下游。

### 4.2 通用性：把数值收敛成一组语义变量

现有覆盖层是散落的硬编码值。建议引入一组 `--fb-*` 变量，下游只改变量即可整体换风格，不必读懂每条选择器：

```css
:root {
    --fb-font-size-base: 14px;      /* 根字号 */
    --fb-line-height-base: 1.571;   /* CJK 行高 */
    --fb-control-height: 32px;      /* 按钮 / 输入框 / 下拉 */
    --fb-page-bg: #f0f2f5;          /* 页面灰底 */
    --fb-card-bg: #fff;             /* 卡片白 */
    --fb-border-color: #dcdfe6;     /* 可见边框 */
    --fb-page-title-size: 20px;     /* 页面标题 */
    --fb-topbar-height: 56px;
    --fb-table-row-padding: 8px;    /* 表格行密度 */
}
```

暗色模式在 `.dark` 下重定义同名变量（现有覆盖层已有 `.dark` 分支的写法可延续）。

### 4.3 风险点

| 风险 | 说明 | 应对 |
|---|---|---|
| **根字号连带缩放 spacing** | Tailwind 4 的 `--spacing: .25rem` 是 rem 基准，根字号 16→14 会让所有 `p-*`/`gap-*` 同步缩 12.5%。可能局部过密 | 改字号后逐页实测；必要时把 `--spacing` 回补为 `0.2857rem`（=4px @14px）保持间距绝对值不变，只缩字号 |
| 图标/头像跟着缩 | 同上，rem 单位的图标会变小 | 关键图标改用 px 固定 |
| 模态框/下拉/日期选择器 | 这些浮层不在主文档流，容易漏测 | 回归清单必须覆盖 |
| 暗色模式 | 新增的背景/边框变量需要 `.dark` 对应值 | 每项同时写两套 |
| 下游已自定义主题 | 下游若已覆盖同名选择器，可能冲突 | 变量化后冲突面收窄；CHANGELOG 明确标注为观感 breaking |

### 4.4 验证方式

1. **视觉回归**：项目已有 Playwright（`tests/e2e/`）。对 8 个关键页面截图前后对比 —— 登录页、仪表盘、列表页（表格）、新建/编辑页（表单）、设置页、角色权限页、模态框、侧栏折叠态。
2. **明暗双模**：每页各截浅色 + 深色。
3. **实测复核**：复用本轮的 `getComputedStyle` 探针脚本，确认目标数值真正落地（避免"写了没生效"，本轮就发现过表头背景规则的判断需要量 `thead` 而非 `th`）。
4. **一屏信息量**：记录列表页一屏可见行数作为量化指标（当前行高 41px）。

### 4.5 建议分期

| 期 | 内容 | 预估 |
|---|---|---|
| 第一期 | P0 全部 5 项 + 变量化骨架 + 视觉回归基线 | 4-6h |
| 第二期 | P1 共 7 项细修 | 3-4h |
| 第三期 | P2 单独立项评估（label 左置 / 多标签页） | 另议 |

## 5. 待确认

1. **根字号方案**：等比缩小（字号 + 间距同缩，国内味最足）还是只缩字号、间距绝对值保持（更可控）？建议前者 + 局部回补。
2. **侧栏宽度**：224px 是否合适？中文菜单最长为「浏览官方市场」6 字，224px 足够；若后续有更长菜单需复核。
3. **`->sidebarWidth()` 写在哪**：写进主包 `FilamentbootPlugin` 里（下游自动继承）还是只改演示项目的 `AdminPanelProvider`（下游自行决定）？前者一致性好，后者侵入性低。
4. 页面背景取 `#f0f2f5`（若依/Ant Pro 更常见）还是 `#f5f5f5`（Ant 5 `colorBgLayout`）？
