# FilamentAdmin 竞品分析

> 更新时间：2026-05-29  
> 文档定位：内部竞品研究与对标判断。本文用于记录 FilamentAdmin 在后台基础能力、平台化能力与插件生态方向上的主要对照样本，不作为对外宣传稿。

## 一、分析范围与用途

本轮竞品分析主要服务于两个判断：

- 当前阶段应该优先补哪些“开箱即见”的后台基础能力。
- 后续插件中心、平台化能力、低代码能力和企业级能力分别可以参考哪些成熟产品。

本轮保留以下竞品作为长期样本：

- FastAdmin
- 若依
- 芋道源码
- JEECG Boot
- PIG
- JeeSite

## 三、这些竞品分别适合拿来参考什么

| 竞品 | 更值得参考的地方 | 对我们当前更直接的启发 |
|------|------------------|------------------------|
| **FastAdmin** | 菜单、配置、附件、插件市场、后台常规操作体验 | 第一版最该补齐的“开箱即见能力”基本都能在这里找到参照物 |
| **若依** | 组织后台信息架构、权限树、菜单树、日志体系、常规管理模块编排 | 适合拿来校正一期“后台基础管理”做完后用户的体感是否完整 |
| **芋道源码** | 从后台底座扩展到商城、CRM、ERP、支付、工作流等业务平台能力 | 适合观察未来插件中心和业务模块如何往“平台化”升级 |
| **JEECG Boot** | 低代码、表单设计、流程、报表、大屏等平台型能力 | 适合作为第二阶段以后“增强型平台能力”的上限参考 |
| **PIG** | OAuth2、认证授权、微服务拆分、云原生部署思路 | 适合给后续 API / 身份体系 / 企业级部署能力做长期参照 |
| **JeeSite** | 长期维护的后台平台结构、插件化思路、数据权限和组织能力 | 适合参考“成熟后台平台如何沉淀规范和可维护性” |

## 四、当前对标结论

- **一期主对标仍应放在 FastAdmin + 若依**：这两类产品最接近“安装完就能明显感知到后台基础能力是否完整”的预期。
- **二期以后再逐步参考芋道、JEECG、PIG、JeeSite**：这些产品更适合拿来校正平台化、低代码、微服务、数据权限和生态化方向，不适合在当前阶段直接照搬范围。
- **FilamentAdmin 当前最缺的不是高级平台能力，而是基础后台能力的显性完成度**：管理员 UI、登录日志 UI、菜单、配置、操作日志、媒体库、导出、个人资料页这些补齐后，产品观感才会从“有底层铺垫”变成“可直接使用”。

## 五、核心功能盘点

### 5.1 认证与用户管理

| 功能 | FastAdmin | 我们的当前状态 |
|------|-----------|----------------|
| **后台登录** | ✓ 含登录日志 | ✅ 已完成：自定义 Filament Login 页，支持 username/email 登录，含 2FA、限速和防枚举攻击 |
| **管理员管理** | ✓ 列表、创建、编辑、删除、状态管理 | ⚠️ 模型层已完成；Filament 管理员 Resource UI 待开发 |

## 六、核心差距详解

1. **权限与菜单**
   - FastAdmin 在默认安装后的显性感知能力，核心就是权限树和菜单树。
   - 我们已经有权限基础，但菜单管理仍为空白；这一块补齐后，用户体感会有明显提升。

2. **系统配置与附件**
   - FastAdmin 的分组配置和附件管理都是开箱可见的能力。
   - 我们目前在这两块都还没有真正落地，对“后台基础平台”的完成度影响很大。

3. **插件生态**
   - FastAdmin 最强的护城河仍然是插件市场与安装体验。
   - 我们的新方向是“`FilamentAdmin` 基础包 + 插件市场基础包”，但第一版连本地扩展清单和插件中心入口都还没落地，这块要尽早建立心智入口。

4. **CRUD 体验**
   - FastAdmin 的一键 CRUD 让人上手很快。
   - 我们不一定需要复制它的生成器路线，但必须把 Filament 官方生成能力和项目自己的规范模板结合起来。
