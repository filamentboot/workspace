# FilamentAdmin 项目后续开发规划

> 更新时间：2026-06-01  
> 文档定位：六期及以后能力规划。五期及以前的收口任务见 `doc/项目开发规划.md`。  
> 前置条件：当前版本完成近期收口，具备可发布、可演示、可二次开发的基础形态后，再进入本文范围。

---

## 一、规划原则

后续开发不再干扰当前版本发布收口。六期及以后按“基础配置能力优先，通用后台能力其次，生态和工程规范最后”的顺序推进。

- 每一期仍然按完整功能块交付，不能只做底层铺垫。
- 每一期都必须包含后台入口、权限、测试、文档和阶段说明。
- 后续能力默认依赖一至五期的稳定基础，不在未收口状态下强行并行扩张。
- 插件相关增强能力必须遵守近期规划里的数据边界：未安装市场条目不长期落本地 MySQL。

## 二、后续分期总览

| 期次 | 功能块 | 优先级 | 目标 |
| --- | --- | --- | --- |
| 六期 | 系统配置 | P0 | 建立配置中心，承载站点配置、上传配置、安全配置、日志配置和插件配置入口。 |
| 七期 | 媒体库 | P1 | 统一文件上传、预览、管理和复用，为头像、Logo、附件、富文本图片打基础。 |
| 八期 | 基础导出 | P1 | 为后台表格提供安全可控的数据导出能力。 |
| 九期 | API 基础规范 | P1 | 定义认证、响应格式、错误码、分页、版本号和 API 文档规范。 |
| 十期 | CRUD 开发规范 | P2 | 沉淀后续业务模块和插件开发模板，避免每个模块重新摸索。 |

## 三、六期：系统配置

六期建立配置中心。它不只是一个“站点名称”页面，而是后续上传、日志、安全、插件能力的统一配置入口。

需要覆盖：

- 基础配置：站点名称、后台标题、Logo、备案信息、联系方式。
- 上传配置：文件大小、允许类型、默认磁盘、图片尺寸策略。
- 安全配置：登录限制、2FA 提示、账号安全开关。
- 日志配置：登录日志和操作日志的保留天数。
- 插件配置入口：插件可以声明自己的 Settings 类，并出现在配置中心。
- 配置缓存：配置变更后缓存能正确失效。

完成标准：后台能修改常用系统配置，业务代码和插件能稳定读取配置。

## 四、七期：媒体库

七期建立统一媒体库，为头像、Logo、富文本图片、附件上传和后续云存储插件打基础。

需要覆盖：

- MediaLibrary 接入：优先使用 Spatie MediaLibrary 和 Filament 官方或社区插件。
- 媒体管理页面：文件列表、预览、下载、删除、筛选。
- Collection 规范：例如 avatar、logo、attachments、content_images。
- 上传安全：文件大小、MIME、扩展名、危险文件拦截。
- 实际场景接入：至少接入管理员头像和系统 Logo，避免媒体库孤立存在。

完成标准：后台能上传、预览、管理文件，并能被真实功能使用。

## 五、八期：基础导出

八期补齐后台高频的数据导出能力。导出不能只是一个按钮，还要考虑权限、字段安全和审计。

需要覆盖：

- 表格导出：优先接入常用 Resource 列表。
- 权限控制：导出需要单独权限点，不等同于 viewAny。
- 字段白名单：敏感字段默认不导出。
- 大数据处理：预留队列导出能力，当前先支持基础同步导出。
- 审计记录：导出行为进入操作日志。

完成标准：管理员能在有权限的列表导出安全字段，导出行为可追踪。

## 六、九期：API 基础规范

九期定义 API 基础规则。这里不追求大而全，重点是让后续插件和业务模块不要各写各的响应格式。

需要覆盖：

- 认证方式：评估 Sanctum 或 Passport，优先轻量方案。
- 响应格式：统一 success、message、data、errors、meta。
- 错误码：定义认证失败、权限不足、参数错误、资源不存在等基础错误。
- 分页格式：统一分页 meta 和 links。
- 版本策略：例如 `/api/v1`。
- 文档方式：选择 OpenAPI、Scribe 或轻量文档方案。
- 权限接入：API 权限与后台权限关系要明确，不默认共用所有后台权限。

完成标准：后续新增 API 有统一规范、测试模板和文档入口。

## 七、十期：CRUD 开发规范

十期沉淀开发规范。这不是给最终用户看的功能，而是给后续开发者和插件作者用的标准模板。

需要覆盖：

- Resource 规范：目录、命名、表单、表格、详情页、权限点。
- Migration 规范：字段命名、软删除、审计字段、索引。
- Model 规范：fillable、casts、scope、policy、activity log。
- 测试规范：Feature、Unit、权限测试、数据权限测试。
- 文档规范：每个功能模块需要有功能说明、权限说明、配置说明。
- 插件规范：插件如何声明菜单、配置、权限、迁移、初始化流程。

完成标准：后续开发新模块时，有可复制的模板和检查清单。

## 八、暂不进入近期主线的范围

以下能力有价值，但在六至十期完成前不作为主线：

- 商业化插件市场、付款、授权、供应商后台。
- 在线升级、在线补丁、远程授权校验。
- 消息通知中心、站内信、短信、邮件模板。
- 队列任务中心、定时任务管理。
- 多语言后台。
- 更完整的安全审计、风控、设备管理。
- 低代码表单、流程引擎、报表设计器。
- 官网和演示站的完整商业化运营体系。

## 九、进入条件

进入本文任何一期前，需要先确认：

- 五期及以前的近期收口任务已完成或明确延期。
- 当前版本已具备可安装、可演示、可发布的状态。
- 对外文档没有把后续规划能力写成已完成。
- 新一期有明确后台入口、权限边界、测试计划和完成标准。
