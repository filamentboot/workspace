# 后台样式改造说明

> 记录 Filamentboot 在 Filament 5 出厂样式之上改了什么、为什么这么改、以后要继续改该怎么下手。
> 调研过程与国内规范对照的原始记录见 [后台观感国产化规划.md](后台观感国产化规划.md)（其中根字号那条结论已被实测推翻，见本文第 4 节）。

目标：把 Filament 的欧美 SaaS 观感调成国内后台观感——**高信息密度、小圆角、边框明显、灰底白卡、控件 32px**，对标若依 / Element Admin / Ant Design Pro。

---

## 1. 改动落在哪三处

| 文件 | 职责 |
|---|---|
| `packages/filamentboot/resources/dist/filamentboot-theme.css` | 绝大部分观感覆盖。**改样式优先改这里** |
| `packages/filamentboot/src/FilamentbootPlugin.php` | 只放 CSS 改不动的项（当前仅侧栏宽度） |
| 演示项目 `app/Providers/Filament/AdminPanelProvider.php` | 主色 / 字体 / 明暗模式等 Panel 级配置，本轮未改 |

### 覆盖机制：为什么不需要 `!important`

Filament 的编译产物全部位于 `@layer components` / `@layer utilities` 中。按 CSS 级联规则，**无 layer 的样式恒胜有 layer 的样式**，与选择器特异性无关。所以 `filamentboot-theme.css` 刻意不写任何 `@layer`，就能用最朴素的选择器覆盖 Filament，且不与 Filament 升级耦合。

加载链路：`FilamentbootServiceProvider::registerThemeAsset()` → `FilamentAsset::register()` → `php artisan filament:assets` 拷到 `public/css/filamentboot/filamentboot/filamentboot-theme.css`。下游 `composer require` 后零配置生效，不需要改 `vite.config.js`、不需要 `npm run build`；文件缺失只会 404 不会白屏。整层可用 `.env` 的 `FILAMENTBOOT_THEME=false` 关闭。

> **改完必须跑 `php artisan filament:assets`**，否则 public 下还是旧文件，改动看不到效果。

### 为什么侧栏宽度必须走 PHP API

Filament 在 `layout/base.blade.php` 里把 `--sidebar-width` **内联写在 `<html>` 元素上**。内联样式优先级高于任何外部样式表，CSS 覆盖层改不动。所以它只能通过 `$panel->sidebarWidth()` 设置——写在 `FilamentbootPlugin::register()` 里，下游继承同一观感，也可以在 `->plugin()` 之后再调一次覆盖（与既有的 `defaultAvatarProvider` 同一套路）。

## 2. 国内基准数值（改动依据）

取国内占有率最高的两条路线，数值均来自各设计体系的 token 源文件。

| 维度 | Ant Design 5 | Element Plus（若依 / vue-element-admin） |
|---|---|---|
| 基准字号 | 14 | 14（small 13 / extra-small 12） |
| **控件高度** | **32**（SM 24 / LG 40） | **32**（large 40 / small 24） |
| 间距阶梯 | 4 / 8 / 12 / 16 / 20 / 24 / 32 / 48 | — |
| 圆角 | 6 | 4（small 2） |
| 边框色 | — | `#dcdfe6` |
| 表格行 padding | — | `8px 0`；单元格 `0 12px` |
| 标题字号 | H1 38 / H2 30 / H3 24 / **H4 20** / H5 16 | — |
| 行高 | `(fontSize+8)/fontSize` → 14px 得 1.571 | — |
| 主色 | `#1677ff` | — |

来源：`ant-design/components/theme/themes/seed.ts`、`shared/genSizeMapToken.ts`、`shared/genFontSizes.ts`；`element-plus/packages/theme-chalk/src/common/var.scss`。

## 3. 逐项改了什么

数值为 Chromium 1600×1000 实测（`getComputedStyle`），非源码推断。

### 3.1 骨架

| 项 | 出厂 | 现在 | 依据 |
|---|---|---|---|
| 侧栏宽度 | 320px（`20rem`） | **224px**（`14rem`） | 国内 208-256 区间 |
| 顶栏高度 | 64px | **56px** | Ant Pro 量级 |
| 页面标题 | 30px / 700 | **20px / 600** | Ant `fontSizeHeading4` |
| 页面底色 | `#fafafa`（近乎纯白） | **`#f0f2f5`** | 若依 / Ant Pro 灰底 |
| 卡片边框 | `ring-gray-950/5`（几乎不可见） | **1px `#dcdfe6`** | Element `$border-color` |
| 主内容区左右留白 | 24px（响应式）| 16px | 提高信息密度 |

### 3.2 控件

| 项 | 出厂 | 现在 | 备注 |
|---|---|---|---|
| 按钮（默认尺寸） | 36px | **32px** | 只收 `fi-size-md`，sm / lg 保持原比例 |
| 输入框 | 36px | **32px** | 出厂 36px 的成因见下 |
| 圆角 | 8-12px | **4-6px** | 改 `--radius-*` token，全站生效 |

输入框出厂 36px 的成因值得记一笔：`.fi-input` 的 `line-height` 取自 `--text-base--line-height`（24px），而字号被改成了 14px——**行高与字号不匹配**才撑到 36px。所以修法是显式给 `line-height: 20px` + `padding-block: 6px`，而不是硬设 height。

### 3.3 表格

| 项 | 出厂 | 现在 |
|---|---|---|
| 行高 | ~57px（`py-4`） | **41px**（`padding-block: 8px`） |
| 表头底色 | 无 | **`#fafafa`** |
| 行 hover | 无底色变化 | **`#f5f7fa`** |
| 数字对齐 | 比例数字 | **`tabular-nums`** |

### 3.4 侧边栏

| 项 | 出厂 | 现在 |
|---|---|---|
| 分组图标 | 24px | **20px** |
| 顶级项图标 | 24px | **20px** |
| 子项前的小圆点 + 竖线 | 显示 | **隐藏**（保留 24px 缩进占位） |

子项标记（`.fi-sidebar-item-grouped-border`）是 Filament 的树形指示器，国内后台惯例是纯文字缩进。隐藏的是标记本身，**缩进占位保留**，所以对齐不变。想恢复原样把 `--fb-sidebar-item-marker-display` 改成 `block`。

### 3.5 表单卡片（本轮唯一的结构性新增）

Filament 的表单默认**直接铺在页面底色上，不套卡片**。出厂底色近乎纯白时看不出来；换成 `#f0f2f5` 灰底后，字段就会"裸浮"在灰面上——所以必须补一层白卡，这也是若依 / Ant Pro 的惯例。

```css
.fi-main form.fi-sc-form:not(:has(.fi-section)):not(:where(.fi-modal *)) { … }
```

两道防御，都已实测验证：

- `:not(:has(.fi-section))` —— 表单自身用了 `Section` 时不套外层卡，避免卡中卡。验证方式：往表单里注入一个 `.fi-section` 子元素，卡片样式立即撤除，移除后恢复。
- `:not(:where(.fi-modal *))` —— 模态框内的表单不套卡（模态框本身已是卡片）。用 `:where()` 是因为它不贡献特异性，防御条件不会让这条规则变得难以覆盖。
- 登录 / 注册页走 `.fi-simple-main` 而非 `.fi-main`，天然不受影响（已实测确认无卡片）。

**这是全局方案而非逐个 Resource 改**：下游自己写的 Resource 表单同样自动获得白卡，不需要在每个 Resource 里手动包 `Section`。

## 4. 刻意没改的（别顺手改）

### 正文字号：不能动

规划阶段曾判断"根字号 16px 是间距偏大的总开关，应压到 14px"——**这个判断是错的**，实测推翻：

`--text-sm = .875rem`，而 Filament 正文（表格单元格、侧栏项、输入框、表单标签、按钮）全部走 `text-sm`。在 16px 根字号下算出来正好是 **14px，已经等于 Ant `fontSize` / Element `$font-size-base`**。把根字号压到 14px，正文会变成 12.25px，反而更糟。

### 行高：不动

Filament 在 14px 字号上用 20px 行高（比值 1.43），比 Ant 的 1.571（22px）更紧——**正合密度目标**。若真要对齐 Ant，得改 `--text-sm--line-height`，那会把按钮、表格行高、侧栏项高度一起顶大 2px，与"更紧凑"的诉求相反。CJK 略紧的代价只在多行段落里体现，后台场景罕见。

### 表单字段间距：不动

字段纵向间距与栅格列间距都是 24px，**与 Ant `Form.Item` 的 `marginBottom` 默认值完全一致**，不是缺陷。国内表单额外的紧凑感来自 label 左置（horizontal）布局，那是结构改动（要动全局 Schema 配置或每个 Resource），成本与风险都另一个量级，未纳入本轮。

### 主色：不动

Panel 已配 `#1677ff` / `#52c41a` / `#faad14` / `#ff4d4f`，与 Ant Design 5 seed token **逐个一致**，无需调整。

## 5. 以后怎么继续改

### 5.1 优先改变量，不要动选择器

所有可调数值收敛在 `filamentboot-theme.css` 顶部的「变量层」：

```css
:root {
    --fb-page-bg: #f0f2f5;          /* 页面灰底 */
    --fb-card-bg: #fff;
    --fb-border-color: #dcdfe6;
    --fb-table-head-bg: #fafafa;
    --fb-table-row-hover-bg: #f5f7fa;
    --fb-control-height: 32px;       /* 按钮 / 输入框 */
    --fb-form-card-padding: 20px;
    --fb-page-title-size: 20px;
    --fb-page-title-line-height: 28px;
    --fb-page-title-weight: 600;
    --fb-topbar-height: 56px;
    --fb-page-header-padding-y: 14px;
    --fb-main-padding-x: 16px;
    --fb-table-cell-padding-y: 8px;
    --fb-sidebar-icon-size: 20px;
    --fb-sidebar-nav-padding: 1rem 0.75rem;
    --fb-sidebar-item-marker-display: none;
    --radius-sm/md/lg/xl/2xl/3xl      /* Filament 圆角 token */
}
```

暗色模式只在 `.dark` 里重定义**配色类**变量，尺寸类规则无需为暗色重复书写——这是变量分层的主要收益。

### 5.2 下游二次定制

下游在自己的样式表里重定义 `--fb-*` 即可，不必读懂每条规则、不必 fork 本文件：

```css
:root { --fb-page-bg: #f5f5f5; --fb-control-height: 28px; }
```

### 5.3 要新增一条覆盖规则时

1. **先实测再动手**。用 `getComputedStyle` 量出当前值和成因，别照着源码猜——输入框 36px 那条如果不实测，很容易误判成"padding 太大"而改错地方。
2. 确认该值是否真能用 CSS 改。凡是 Filament 内联在元素上的（如 `--sidebar-width`），必须走 PHP API。
3. 新数值优先取 4 的倍数，向第 2 节的基准表对齐；能复用现有变量就别新造。
4. 只收默认尺寸档（`fi-size-md`），别把 `sm` / `lg` 一起改，否则破坏 Filament 的尺寸比例体系。
5. 改完 `php artisan filament:assets`，然后按 5.4 回归。

### 5.4 回归清单

改任何观感项后至少覆盖这 8 处，浅色 + 暗色各看一遍：

- 登录页（`.fi-simple-*` 布局，不受 `.fi-main` 规则影响，最容易被漏测）
- 仪表盘（Widget 卡片）
- 列表页（表格密度、表头、hover、分页）
- 新建 / 编辑页（表单卡片、控件高度）
- 设置页（Page 型表单）
- 模态框（卡中卡风险）
- 侧栏折叠态（分组图标 + 悬浮子菜单）
- 侧栏展开态（缩进、图标尺寸、高亮）

本轮实测结果：侧栏 224px / 顶栏 56px / 标题 20px·600 / 底色 `rgb(240,242,245)` / 卡片边框 1px `rgb(220,223,230)` / 按钮 32px / 输入框 32px / 表格行 41px / 表头 `rgb(250,250,250)` / 图标 20px；暗色底色 `gray-950`、边框 `rgba(255,255,255,.1)`。`php artisan test` 526/526 通过。

## 6. 已知遗留（不属于样式，需另立任务）

1. **界面英文残留**：`APP_LOCALE=en` 导致大量框架文案仍是英文——页面标题 `Dashboard` / `General Settings Page`、面包屑 `List` / `Create`、按钮 `Create & create another` / `Cancel` / `Save changes`、`Search` / `Per page` / `Showing 1 to 6 of 6 results`、上传区 `Drag & Drop your files or Browse`、`Select an option`。**这是目前"不像国内后台"最大的单项残留，观感改造无法覆盖，属 i18n 工作。**
2. **翻译键裸露**：列表页操作列直接显示 `filament-impersonate::action.label`，该包的语言文件未发布或未翻译。
3. 表格在窄视口会横向溢出（impersonate 列被截断）。
4. 站点插件（`官网管理` 分组）当前不显示：开发库重置后 `plugins` 表为空，`registerEnabledPlugins()` 没注册它，其路由不存在导致菜单被 `Route::has()` 过滤。与本轮改动无关。
