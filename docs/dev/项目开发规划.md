# FilamentAdmin 近期开发规划

> 更新时间：2026-06-01  
> 文档定位：五期及以前的开发收口规划。本文只记录当前版本发布前还需要开发、修正或补齐的事项。  
> 后续规划：六期及以后见 `doc/项目后续开发规划.md`。

---

## 一、规划原则

项目已经正式上线。 

- 对现有功能完全收口。 不要再出现任何未收口闭环的功能。 
- 规划一下现有版本。 规划本期要做哪些？ 
- 每个任务必须能对应到五期及以前的收口目标。
- 已经完成的能力不再重复展开，只记录仍需补齐、修正或验收的部分。
- 插件市场先完成基础架构和安装链路收口，不进入复杂商业化、在线升级和生态运营。
- 插件市场的数据边界必须清晰：除“已安装插件、本地启停状态、初始化状态、安装/操作日志、必要运行记录”外，官方市场目录、远程索引、搜索结果和未安装插件详情不应长期写入本地 MySQL。

## 三、近期开发顺序

1. P0：修正插件市场数据模型边界。官方市场浏览数据不落本地 MySQL，本地只保留已安装插件和运行状态。
2. P0：补齐插件启停与初始化。启停要真实影响后台导航、Resource、Page、配置项和服务注册；初始化要支持迁移、资源发布、种子数据和失败重试。
3. P0：补齐一期发布前缺口。包括默认管理员/角色/菜单初始化、权限点复核、日志保留策略、2FA 恢复流程和最终验收清单。
4. P0：推进五期发布体验。补齐后台首页、README/安装文档、CI、发布说明、截图和演示入口。
5. P1：优化插件安装链路体验。Composer 安装需要更清晰的进度反馈、失败恢复、日志查看、进程重载提示和安全校验。
6. P1：完成上线资料收口。补齐部署清单、环境变量说明、回滚说明、Release Notes、CHANGELOG 和阶段 Tag 记录。
7. P1：完成 Packagist.org 注册与包发布流程收口。注册 filament-admin 组织/账号，配置 `composer.json`，发布到 Packagist，确保 `composer require filament-admin/filament-admin` 可用。
8. P1：建立演示站（demo.xitongapp.com）基础。使用独立仓库 filament-admin-demo，部署到 demo.xitongapp.com，含演示账号体系和定时数据重置机制。

## 四、任务明细

### 4.1 插件市场数据边界修正

目标：插件市场可以浏览远程官方索引，但未安装插件不成为本地业务数据。

需要完成：

- 官方市场列表、搜索、详情优先从远程索引读取。
- 如需缓存，只使用 HTTP 缓存、应用缓存或短期文件缓存，不长期写入 MySQL 市场目录表。
- 本地数据库只保留已安装插件、本地启停状态、初始化状态、安装日志和必要运行记录。
- “同步官方市场”类文案需要调整为“刷新官方市场”“浏览官方市场”或更准确的表达，避免用户误解为导入本地数据库。
- 安装动作发生后，才把对应插件写入本地已安装插件状态。

完成标准：后台能浏览官方市场并安装可信插件；除用户实际安装的插件外，市场条目不落本地 MySQL。

### 4.2 插件启停与初始化

目标：插件不是只在列表里改变状态，而是真实影响后台能力。

需要完成：

- 启用插件后注册对应导航、Resource、Page、配置入口和服务能力。
- 禁用插件后隐藏对应导航、Resource、Page 和配置入口。
- 插件初始化支持迁移、资源发布、种子数据和初始化记录。
- 初始化失败时保留日志和可重试入口。
- 禁用被依赖插件时给出阻断或明确风险提示。

完成标准：后台插件状态与实际可见能力一致，初始化过程可追踪、可失败恢复。

### 4.3 后台基础管理补齐

目标：一期能力进入发布前稳定状态。

需要完成：

- 提供默认管理员、超级管理员角色、基础权限和基础菜单的初始化方式。
- 复核管理员、角色、菜单、部门、数据权限、登录日志、操作日志的权限点覆盖。
- 补齐登录日志和操作日志的保留策略、清理命令或配置入口。
- 复核 2FA 启用、关闭、恢复码和异常登录体验。
- 整理一期验收清单，明确哪些能力已完成、哪些只是预留。

完成标准：新环境安装后能完成基础初始化，后台基础管理能力可稳定演示。

### 4.4 五期发布体验

目标：把当前版本从“能用”整理成“可发布”。

需要完成：

- 后台首页展示真实统计，如管理员数、登录日志、插件状态、系统状态。
- 快捷入口覆盖管理员管理、角色权限、菜单管理、插件中心、文档入口。
- README 和公开文档明确项目定位、已完成能力、安装步骤和当前限制。
- 安装文档覆盖环境要求、数据库、迁移、创建管理员、本地域名和常见问题。
- CI 至少覆盖 test、phpstan、pint 和 composer audit。
- 发布材料包含 CHANGELOG、Release Notes、Tag 约定和升级说明。
- 明确 `filamentadmin` 官网与演示站的边界，当前先保证文档和演示入口清晰。

完成标准：新用户能按文档安装项目，能理解当前已完成能力和后续规划，项目具备阶段公开发布条件。

### 4.5 上线资料收口

目标：四期上线动作形成可执行、可回滚、可复盘的流程。

需要完成：

- 整理上线清单，区分必须上线和可延后事项。
- 明确环境变量、PHP 扩展、数据库、缓存、队列、定时任务和文件权限要求。
- 明确构建、部署、回滚、验收和复盘步骤。
- 补齐 Gitee 分支、Tag、Release、变更公告和回滚约定。
- 至少完成一次按文档执行的发布演练记录。

完成标准：团队可以按文档稳定完成一次发布，并能在失败时按回滚方案处理。

### 4.6 Packagist.org 注册与包发布

目标：让开发者可以通过 Composer 标准方式安装 FilamentAdmin。

需要完成：

- 注册 Packagist.org 账号，组织名使用 `filament-admin`。
- 复核 `composer.json`：确认 `name`（`filament-admin/filament-admin`）、`description`、`keywords`、`homepage`、`license`（MIT）、`authors`、`support` 字段完整。
- 确认 `composer.json` 的 `minimum-stability` 和 `prefer-stable` 配置。
- 在 Packagist 提交包，绑定 GitHub/Gitee 仓库，配置 Webhook 实现版本自动同步。
- 发布首个可用版本 Tag（遵循 SemVer，如 `v1.0.0-beta.1`）。
- 在 README 中替换徽章占位符为真实 Packagist 链接。
- 验收标准：执行 `composer require filament-admin/filament-admin` 可以正常安装。

### 4.7 演示站建设

目标：提供在线可访问的 FilamentAdmin 演示环境，降低用户评估门槛。

需要完成：

- 建立独立 Git 仓库 `filament-admin-demo`，从主仓库派生，叠加演示专用配置（`.env.demo`、演示账号 Seeder、高危操作屏蔽中间件）。
- 演示账号体系：超级管理员（只读，无法删除核心数据）、普通管理员、编辑角色各一套，密码公开展示。
- 高危操作屏蔽：禁止删除管理员账号、清空日志、修改超管密码，Middleware 拦截并提示「演示站限制」。
- 定时数据重置：Artisan 命令 `demo:reset`，配合 Schedule 每小时或每天重置演示数据。
- 部署到 `demo.xitongapp.com`，配置 SSL。
- 完成标准：访客可以访问演示站、使用演示账号登录、直观感受后台能力，且操作不会造成破坏性后果。




## 六、验收和维护规则

- 每完成一个收口任务，都要同步更新状态、测试记录和相关功能文档。
- 对外文档必须继续区分“已完成 / 已铺垫 / 待开发”，宁可保守，不虚标完成度。
