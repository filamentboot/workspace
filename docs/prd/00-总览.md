## 1. 执行摘要

FilamentAdmin 是一个基于 Laravel 13 + Filament 5 的后台基础平台,解决新项目重复搭建后台基础设施的问题。通过提供**开箱即用的插件市场**和**组合最优的代码基座**,让开发者执行 `composer create-project` 后获得完整后台底座,可直接开始业务开发。第一版聚焦后台基础能力闭环(认证、权限、日志、菜单),后续逐步补齐插件市场完整链路、发布体验和生态建设。

## 2. 问题陈述

### 2.1 谁有这个问题?

| 用户类型 | 典型场景 | 痛点 |
|---------|---------|------|
| **独立开发者** | 接外包项目或做自己的 SaaS 产品 | 每次新项目花 1-2 周搭后台,重复造轮子 |
| **小团队(1-10人)** | 创业公司快速验证产品 | 后台基础代码质量参差不齐,安全漏洞风险 |
| **外包公司** | 多项目并行交付 | 每个项目后台各自演进,无法共享升级路径 |
| **企业 IT 部门** | 内部管理系统建设 | 权限管控、操作审计、登录安全要求严格 |

### 2.2 问题是什么?

每个新的 Laravel 后台项目都要重复解决以下通用能力:

1. **认证体系**:管理员登录、2FA、登录日志、登录限流
2. **权限管理**:RBAC、菜单权限、数据权限、角色分配
3. **后台导航**:菜单管理、权限绑定、插件菜单接入
4. **日志审计**:操作日志、登录日志、审计追踪
5. **系统配置**:站点配置、上传配置、插件配置
6. **扩展机制**:插件安装、启停、初始化、配置
7. **文件管理**:本地存储、云存储扩展点
8. **开发规范**:Model、Migration、Seeder、Policy、Resource 组织方式

### 2.3 为什么痛苦?

- **时间成本**:每次搭建后台基础需要 1-2 周,按开发者日均成本计算损失数千到数万元
- **质量风险**:重复造轮子容易引入安全漏洞(权限绕过、SQL 注入、CSRF)
- **维护负担**:每个项目的后台基础代码各自演进,无法共享升级路径
- **学习曲线**:新成员加入项目需要重新理解后台实现逻辑

### 2.4 证据

- **FastAdmin 下载量超过 10 万次**,证明"开箱即用的后台基础平台"是真实刚需
- **若依框架 GitHub Stars 超过 3 万**,说明国内开发者对完整后台解决方案的强烈需求
- **Laravel 社区高频问题**:Filament 官方论坛和 Discord 中,"如何快速搭建完整后台"是常见问题
- **竞品空白**:Laravel 生态中缺少像 FastAdmin 那样"安装完就能用"的完整后台基础包

- **TAM**:全球 Laravel 开发者约 200 万(基于 Packagist 活跃用户和 GitHub 数据)
- **SAM**:中国 Laravel/Filament 开发者约 20 万(基于社区活跃度估算)

### 4.3 竞争格局

| 竞品 | 优势 | 劣势 | 我们的差异化 |
|------|------|------|-------------|
| **FastAdmin** | 插件市场成熟,国内用户多 | 基于 ThinkPHP,技术栈老旧 | Laravel + Filament 现代化技术栈 |
| **若依** | 功能全面,文档详细 | Java 技术栈,重 | PHP 轻量级,安装简单 |
| **Filament 官方** | 框架强大,社区活跃 | 只提供基础框架,不提供完整后台 | 开箱即用的完整后台 + 插件市场 |

### 4.4 为什么现在?

1. **Filament 5 已稳定**:API 趋于稳定,适合在其上构建完整后台基础包
2. **Laravel 13 成熟**:提供更好的依赖注入、队列、事件系统,适合做插件机制
3. **市场空白**:Laravel 生态中缺少"安装完就能用"的完整后台解决方案
4. **开发者需求**:社区中频繁出现"如何快速搭建后台"的讨论

## 5. 解决方案概述

### 5.1 产品定位

FilamentAdmin 提供**一个可安装的 Composer 包**,执行 `composer create-project filament-admin/skeleton` 后获得完整后台底座。

### 5.2 核心能力

| 能力域 | 描述 | 技术实现 |
|--------|------|---------|
| **认证体系** | 管理员登录(username/email)、2FA、登录日志、登录限流 | Filament 5 + stephenjude/filament-two-factor-authentication |
| **权限管理** | Spatie Permission + Shield 4.x,角色、菜单权限、数据权限 | spatie/laravel-permission + bezhansalleh/filament-shield |
| **后台 UI** | Filament 5 Panel Builder,深色侧边栏,自定义品牌色 | filament/filament |
| **日志系统** | 操作日志 + 登录日志 | spatie/laravel-activitylog + 自定义登录日志表 |
| **插件市场** | 独立 Composer 基础包,插件浏览、安装、启停、初始化 | packages/plugin-platform/ |
| **系统配置** | 强类型配置类 + Filament 配置页 | spatie/laravel-settings + filament 插件 |
| **媒体库** | 本地存储 + 云存储插件扩展点 | spatie/laravel-medialibrary |
| **API 基础** | Sanctum Bearer Token + 统一响应格式 | laravel/sanctum |

### 5.3 关键用户流程

#### 流程 1:新用户安装和使用

```
1. 执行 composer create-project filament-admin/skeleton my-admin
2. 配置 .env(数据库、Redis、邮件等)
3. 执行 php artisan migrate --seed
4. 访问 http://localhost/admin,使用默认管理员账号登录
5. 看到后台首页,包含管理员数、登录日志、插件状态等统计卡片
6. 开始创建自己的业务模块
```

#### 流程 2:安装插件

```
1. 进入后台 → 插件中心 → 浏览官方市场
2. 选择一个插件(如"云存储 OSS")
3. 点击"安装"按钮
4. 显示安装进度(队列任务)
5. 安装完成后提示"启用插件"
6. 启用后,后台导航出现新菜单项
7. 如需初始化,进入初始化向导(导入演示数据、配置权限等)
```

#### 流程 3:配置角色权限

```
1. 进入后台 → 角色管理 → 创建新角色"编辑"
2. 勾选允许的菜单和资源操作
3. 配置数据权限范围(本部门/本人/全部)
4. 将角色分配给管理员
5. 该管理员登录后只能看到授权的菜单和操作
```

## 7. 功能需求

### 7.1 一期:后台基础管理完整包(已完成)

| 功能 | 描述 | 验收标准 |
|------|------|---------|
| **管理员登录** | 支持 username 或 email 登录 | 登录限流、登录日志、明确错误信息 |
| **双因素认证** | TOTP + Recovery Code | 个人设置启用/关闭、QR Code 扫描、恢复码登录 |
| **管理员管理** | 创建、编辑、禁用管理员 | 软删除、回收站、角色分配 |
| **角色权限** | Spatie Permission + Shield 4.x | 角色创建、权限勾选、超级管理员绕过 |
| **菜单管理** | 后台导航菜单管理 | 树形结构、拖拽排序、权限绑定、插件菜单接入 |
| **登录日志** | 记录登录行为 | IP、UA、时间、成功/失败、只读 |
| **操作日志** | spatie/laravel-activitylog | 操作人、对象、类型、时间、diff、只读 |
| **部门与数据权限** | 部门树 + 数据范围过滤 | 全部/本部门/本人、Resource scopeQuery 注入 |

### 7.2 二期:插件市场基础包(基本完成)

| 功能 | 描述 | 验收标准 |
|------|------|---------|
| **插件市场架构** | 独立 Composer 基础包 | 依赖 FilamentAdmin,独立版本管理 |
| **插件列表与状态** | 查看已安装插件 | 名称、版本、状态(启用/禁用/待初始化) |
| **插件启停** | 启用/禁用插件 | 真实影响导航、Resource、Page、配置入口 |
| **插件初始化** | 迁移、发布资源、种子数据 | 失败重试、日志记录、状态流转 |
| **插件配置** | 插件 Settings 类 + 配置页 | 配置缓存、操作日志 |

### 7.3 三期:远程插件市场索引(基本完成)

| 功能 | 描述 | 验收标准 |
|------|------|---------|
| **远程索引读取** | 浏览官方插件市场 | JSON 索引、不长期写 MySQL、HTTP 缓存 |
| **插件详情与安装** | 查看插件详情并安装 | 仅官方可信来源可安装、安装指引 |

## 8. 不在范围内

### 8.1 第一版不包含

| 能力 | 原因 | 规划版本 |
|------|------|---------|
| 前台会员模块 | 后台权限和前台用户权限必须分开 | v2.0.0 |
| 复杂多语言 | 第一版只预留语言包扩展方式 | v2.0.0 |
| 在线升级 | 第一版升级靠手动命令 | v2.0.0 |
| 付费插件和商业化 | 第一版只做字段预留 | v2.0.0 |
| 异步安装队列 | 第一版同步安装,简单可靠 | v2.0.0 |
| 队列监控/Horizon | 适合第二版运维能力 | v2.0.0 |
| API 文档生成 | 暂不纳入第一版 | v2.0.0 |
| 全局回收站 UI | 第一版只做软删除能力 | v2.0.0 |

### 8.2 边界声明

- 后台权限和前台用户权限必须分开设计
- 扩展包只解决通用能力,不承担核心业务逻辑
- 数据权限第一版先实现角色级范围控制,不做字段级权限
- 主包只装"绝大多数后台项目都会用到"的基础能力

## 9. 依赖与风险

### 9.1 技术依赖

| 依赖 | 用途 | 风险等级 | 缓解措施 |
|------|------|---------|---------|
| Laravel 13 | 框架基础 | 低 | 锁定主版本,patch/minor 自由升级 |
| Filament 5 | 后台 UI 框架 | 中 | 参考官方示例,避免实验性 API |
| Spatie Permission | 权限基础 | 低 | 使用 Shield 4.x 兼容版本 |
| spatie/laravel-activitylog | 操作日志 | 低 | 固定使用 4.x,不升级到 5.x |
| stephenjude/filament-two-factor-authentication | 2FA | 中 | 评估替代方案,预留切换空间 |

### 9.2 风险与缓解

| 风险 | 影响 | 概率 | 缓解措施 |
|------|------|------|---------|
| 插件市场数据模型设计错误 | 未安装插件数据污染本地 MySQL | 中 | 严格区分"浏览数据"和"已安装数据" |
| 插件启停不影响实际能力 | 用户点击启用后看不到新菜单 | 中 | 启停必须真实注册/注销 Service Provider |
| 安装文档不清晰 | 用户安装失败率高 | 高 | 发布前至少 3 人按文档独立安装测试 |
| 安全漏洞 | 权限绕过、SQL 注入 | 低 | PHPStan level 6、Pest 测试覆盖、安全审计 |
| Filament 5 API 变更 | 升级后功能失效 | 中 | 锁定主版本,关注官方更新日志 |
