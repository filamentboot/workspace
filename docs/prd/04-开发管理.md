> 文档定位:FilamentAdmin 开发管理功能域产品需求文档,覆盖 API 基础规范、CRUD 开发规范、项目文档规范
> 
> 更新时间:2026-06-02
> 
> 文档状态:待开发
> 
> 版本:v0.3.0

---

## 1. 执行摘要

建立开发规范,包含 API 基础规范(Sanctum 认证、响应格式、错误码、分页、文档)、CRUD 开发规范(Resource/Migration/Model/测试/文档/插件规范模板)、项目文档规范整理,为后续开发者和插件作者提供标准模板。

---

## 2. 问题陈述

### 2.1 谁有这个问题?

FilamentAdmin 开发者和插件作者需要开发新模块和 API,但当前没有统一的开发规范和 API 标准,各模块各写各的响应格式。

### 2.2 问题是什么?

- 没有统一的 API 认证方式和响应格式
- 没有 Resource、Migration、Model 开发规范
- 没有测试模板给后续开发者参考
- 项目文档分散,没有统一规范

### 2.3 为什么痛苦?

- 前端需要适配多种响应格式
- 新模块开发效率低,需要重新摸索
- 代码风格不一致,维护成本高
- 文档质量参差不齐

---

## 3. 目标用户

### 主要角色:后端开发者和前端开发者

- 后端开发者:负责开发 FilamentAdmin 新模块或插件
- 前端开发者:负责对接 FilamentAdmin API

**Jobs-to-be-Done**:
> "当开发新模块时,我想要标准模板和检查清单,这样可以快速开发且符合项目规范。"
> "当需要对接 API 时,我想要统一的 API 规范,这样可以快速理解响应格式、错误处理和认证方式。"

---

## 4. 解决方案概述

### 4.1 核心能力

| 能力域 | 描述 | 技术实现 |
|--------|------|---------|
| API 基础规范 | Sanctum 认证、响应格式、错误码、分页、文档 | laravel/sanctum + knuckleswtf/scribe |
| CRUD 开发规范 | Resource/Migration/Model/测试/文档/插件规范模板 | 模板文件 + 基类 + Trait |
| 项目文档规范 | 文档目录结构、命名规范、模板、README、安装指南、开发规范 | Markdown 文档体系 |

### 4.2 关键用户流程

#### 流程 1:API 认证

```
1. 前端请求 /api/v1/login,传入 username/email 和 password
2. 后端验证成功,返回 access_token
3. 后续请求携带 Authorization: Bearer {token}
4. 后端验证 token,返回数据
```

#### 流程 2:开发新模块

```
1. 复制 Resource 模板
2. 修改模型名称、字段
3. 创建 Migration,使用模板字段
4. 创建 Model,使用基类和 Trait
5. 创建测试,使用测试模板
6. 创建文档,使用文档模板
7. 运行测试,确认通过
```

## 5. 功能需求

### 5.1 API 基础规范

| 需求 | 描述 | 验收标准 |
|------|------|---------|
| 认证方式 | Sanctum Bearer Token | laravel/sanctum |
| 响应格式 | 统一 success、message、data、errors、meta | Response Macro |
| 错误码 | 基础错误码定义(401/403/404/422/500) | 错误码常量 |
| 分页格式 | 统一分页 meta 和 links | Laravel Paginator |
| 版本策略 | /api/v1 路由 | 路由分组 |
| 文档方式 | Scribe 自动生成 | knuckleswtf/scribe |
| 权限接入 | API 权限与后台权限关系明确 | 独立 Guard 或复用 |

### 5.2 CRUD 开发规范

| 需求 | 描述 | 验收标准 |
|------|------|---------|
| Resource 规范 | 目录、命名、表单、表格、详情页、权限点 | 模板文件 |
| Migration 规范 | 字段命名、软删除、审计字段、索引 | 模板文件 |
| Model 规范 | fillable、casts、scope、policy、activity log | 基类 + Trait |
| 测试规范 | Feature、Unit、权限测试、数据权限测试 | 测试模板 |
| 文档规范 | 功能说明、权限说明、配置说明 | 文档模板 |
| 插件规范 | 插件如何声明菜单、配置、权限、迁移、初始化 | 插件开发指南 |

### 5.3 项目文档规范

| 需求 | 描述 | 验收标准 |
|------|------|---------|
| 文档目录结构 | 统一 docs/ 目录结构,区分功能文档、开发文档、部署文档 | docs/features/、docs/development/、docs/deployment/ |
| 命名规范 | 文档命名统一小写 + 连字符,功能文档用功能名,开发文档用主题名 | 如 authentication.md、custom-permissions.md |
| 文档模板 | 提供功能文档模板、开发规范模板、API 文档模板 | 模板包含标准章节结构 |
| README.md | 项目定位、已完成能力、安装步骤、当前限制、文档索引 | 清晰完整,新用户可按文档安装 |
| 安装指南 | 环境要求、数据库配置、迁移、创建管理员、本地域名、常见问题 | 步骤清晰,可执行 |
| 开发规范 | 代码风格、命名规范、Resource 组织方式、测试规范、Git 提交规范 | 开发者可按规范开发新模块 |
| 文档索引 | docs/README.md 或 docs/index.md,列出所有文档及用途 | 方便查找 |
