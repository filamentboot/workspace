## 2. 第一阶段：代码整理与发版 (v0.4.0)

### 2.1 问题陈述

FilamentAdmin 维护者需要发布项目到 Packagist,但当前代码结构不适合直接作为 Composer 包发布,仓库也不规范。新用户安装后没有默认数据,无法登录。

### 2.2 核心能力

| 能力域 | 描述 | 技术实现 |
|--------|------|---------|
| 代码整理 | 清理无用代码、规范目录结构、统一命名 | Pint 格式化、PHPStan 检查 |
| 仓库整理 | README、CHANGELOG、LICENSE、.gitignore | Markdown 文档 |
| 默认数据初始化 | SuperAdminSeeder、AdminFoundationMenuSeeder、安装流程说明 | Laravel Seeder + 安装文档 |
| Packagist 注册 | 注册组织、配置 composer.json | Packagist.org |
| 版本发布 | Tag、Release Notes、Webhook | GitHub/Gitee Release |

### 2.3 关键用户流程

```
1. 执行 composer require filament-admin/filament-admin
2. Composer 从 Packagist 下载包
3. 按安装文档配置环境
4. 执行 php artisan migrate --seed
5. 访问后台,使用默认管理员账号登录(admin@example.com / password)
```

### 2.4 功能需求

#### 国际化（i18n）

| 需求 | 描述 | 技术实现 |
|------|------|---------|
| 零配置中文 UI | 用户 `composer require` 后无需额外配置即呈现中文界面 | 详见下方技术说明 |
| APP_LOCALE 文档说明 | 安装文档注明需在宿主应用设置 `APP_LOCALE=zh_CN` | 安装文档 |

**技术说明**

Filament 核心及主要依赖（shield、activity-log、filament-tree）均已提供 `zh_CN` 翻译，宿主应用设置 `APP_LOCALE=zh_CN` 即可自动切换。

唯一例外：`stephenjude/filament-two-factor-authentication` 无 `zh_CN` 翻译。该包使用独立翻译命名空间 `filament-two-factor-authentication`，无法借用 Filament 核心翻译目录。

解决方案：在 Library 包的 `ServiceProvider::boot()` 中通过 `loadTranslationsFrom` **以相同命名空间注册** zh_CN 翻译，覆盖该包的 `en` 翻译，实现零配置中文：

```php
// src/FilamentAdminServiceProvider.php
public function boot(): void
{
    // 内置 2FA 包的中文翻译，宿主应用无需额外发布
    $this->loadTranslationsFrom(
        __DIR__.'/../resources/lang/vendor/filament-two-factor-authentication',
        'filament-two-factor-authentication',
    );
}
```

翻译文件放在 `src/resources/lang/vendor/filament-two-factor-authentication/zh_CN/`，包含 5 个文件：`actions.php`、`components.php`、`pages.php`、`plugin.php`、`section.php`。

> **验收标准**：`composer require` 后，2FA 设置页面（启用/禁用/恢复码等）全部显示中文，无需用户执行任何发布命令。
