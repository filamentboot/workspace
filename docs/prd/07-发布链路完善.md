## 2. 下次手动发布流程

下次发版时，按以下顺序执行，不要跳步。

### 2.1 发布前检查

1. 在根仓库确认工作区干净：

```bash
git status --short
```

2. 确认根仓库测试通过：

```bash
./vendor/bin/phpunit tests/Unit/Release/DemoAppPackageBridgeTest.php
```

3. 确认包目录测试通过：

```bash
cd packages/filament-admin
../../vendor/bin/phpunit -c phpunit.xml.dist
cd ../..
```

4. 确认包元数据无误：

```bash
composer validate
cd packages/filament-admin && composer validate && cd ../..
```

5. 更新版本说明：
- 根仓库 `CHANGELOG.md`
- 包目录 `packages/filament-admin/CHANGELOG.md`
- 必要时同步 README / wiki / 发布文档

### 2.2 提交根仓库

1. 提交当前改动：

```bash
git add .
git commit -m "chore: 准备 vX.Y.Z 发布"
```

2. 推送演示项目仓库：

```bash
git push -u preview main
```

### 2.3 生成纯包分支

从根仓库 split 包目录：

```bash
git subtree split --prefix=packages/filament-admin -b release/filament-admin-package-vX.Y.Z
```

成功后记录 split commit SHA。

### 2.4 推送包仓库

1. 推送到 GitHub 包仓库：

```bash
git push package-github release/filament-admin-package-vX.Y.Z:main --force
```

2. 推送到 Gitee 包仓库：

```bash
git push package-gitee release/filament-admin-package-vX.Y.Z:main --force
```

### 2.5 创建标签

标签必须打在 split 后的纯包提交上，不打在根仓库 `main` 提交上。

```bash
git tag -a vX.Y.Z <split-commit-sha> -m "vX.Y.Z 发布"
git push package-github vX.Y.Z
git push package-gitee vX.Y.Z
```

### 2.6 创建 GitHub Release

```bash
gh release create vX.Y.Z \
  --repo john-captain/filament-admin \
  --title vX.Y.Z \
  --notes "从 CHANGELOG 提炼本次发布说明"
```

检查项：

- Release 对应的 tag 正确
- Release 正文与 `CHANGELOG.md` 一致
- GitHub 仓库首页安装命令仍为 `composer require laravelstack/filament-admin`

### 2.7 验证 Packagist

1. 检查 Packagist 是否已识别到新版本：

```bash
composer show laravelstack/filament-admin --available
```

2. 在干净 Laravel 项目中执行：

```bash
composer require laravelstack/filament-admin
```

成功标准：

- 能解析到新版本
- 依赖安装成功
- `package:discover` 成功

### 3.1 已完成

  - 文件：`packages/filament-admin/.github/workflows/ci.yml`
  - 作用：`push` / `tag` / `pull_request` 时执行 `composer install` 和包测试

1. **自动 split 发布**
- 目前仍需手工执行 `git subtree split`
- 没有 GitHub Action 自动将 `packages/filament-admin` 发布到包仓库

2. **自动创建 GitHub Release**
- 当前使用 `gh release create` 手工创建
- 没有 tag 驱动的自动 Release 工作流

3. **Packagist 自动更新验证**
- 这次已完成首次提交
- 但没有再做一次“新 tag 推送后自动同步到 Packagist”的回归验证
- 因此不能把“hook 已稳定可用”写成已完成

4. **失败回滚脚本**
- 当前没有一键回滚脚本
- 标签、Release、split 分支、远端主分支都需要手工处理
