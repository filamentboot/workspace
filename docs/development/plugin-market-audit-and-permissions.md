# 插件市场审计与权限说明

## 当前访问边界

- 插件市场当前运行在 `admin` 面板内
- 访问前提仍是通过 `admin` guard 完成后台认证
- 当前阶段尚未为插件市场单独拆出细粒度资源权限点
- 因此当前访问控制语义是：
  - 已进入后台的管理员可以看到插件市场入口
  - `系统基础依赖`、`扩展清单`、`官方市场` 共享当前后台访问边界

这是一条**当前实现事实**，不是长期目标。  
如果后续要把插件市场开放给非超级管理员使用，建议再补：

- 市场查看权限
- 扩展安装权限
- 扩展启停权限
- 初始化执行权限
- 市场同步权限

## 当前操作审计事件

插件市场当前已经写入以下后台操作日志事件：

- `plugin_installed`
- `plugin_install_failed`
- `plugin_enabled`
- `plugin_disabled`

这些事件统一写入 `admin` 日志通道，便于和后台现有操作日志视图对照。

## 当前审计内容

安装与状态变更事件当前会记录：

- 操作人
- 操作对象
- 变更前状态
- 变更后状态
- IP
- User Agent

这意味着当前已经能追踪：

- 谁安装了某个官方可信来源插件
- 谁启用了某个普通插件
- 谁禁用了某个方案型插件
- 某次安装失败时系统把状态改成了什么

## 当前未纳入审计的范围

以下能力当前还没有进入更细粒度审计：

- 官方市场索引内容本身的差异对比
- 初始化步骤中的分阶段细项审计
- 启停动作对真实菜单、页面、配置入口的运行时影响

原因是这些链路当前仍停留在基础平台阶段，尚未接到真实远程索引、真实 Composer 执行器或真实插件级初始化执行器。

## 权限与审计的下一步建议

如果后续继续推进插件市场，建议优先补下面两类能力：

1. 插件市场专属权限点
2. 初始化与市场同步的更细日志

这样才能把“可见”“可装”“可启停”“可初始化”拆成真正独立的后台授权动作。
