#### ✅ #12 · 2-2 区块契约与注册表（已完成）

落点：`src/Cms/Blocks/{BlockContract,AbstractBlock,BlockRegistry}.php` + 七个区块类（`HeroBlock`、`RichContentBlock`、`MediaTextBlock`、`FeatureGridBlock`、`CtaBlock`、`FaqBlock`、`ContactFormBlock`），在 `SiteServiceProvider::register()` 中注册为容器单例。测试：`tests/Unit/Cms/BlockRegistryTest.php`（31 例）。

#### A1 · 线索来源与归因落库（2h）

**这是一个已经做了一半的实现，优先级最高。**

现状证据：
- `resources/views/shared/components/contact-panel-store.blade.php` 的 Alpine store **已经有 `source` 字段**，`show(source)` 会记录是哪个按钮触发的
- 各处 CTA 也都带了 `data-contact-trigger="floating|hero|nav-desktop|nav-mobile|home-cta|product-card|solution-detail|case-detail|product-detail"`
- 但 `floating-contact.blade.php:82` 的 `@livewire('filamentboot-site::contact-form')` **不传任何参数**
- `src/Http/Livewire/ContactForm.php` **没有 `source` 属性**
- `2026_06_13_000017_create_site_contact_messages_table.php` 只有 name / phone / message / status / ip **五列**

结果：埋点入口全做了，数据一列没落。后台看到一条询盘，不知道访客从哪个页面、点哪个按钮、走哪个渠道来的。

要做：
1. 迁移给 `site_contact_messages` 加 `source`、`landing_url`、`referer`、`utm_source`、`utm_medium`、`utm_campaign`、`utm_term`、`utm_content`
2. `ContactForm` 增加 `source` 属性，打开面板时由 Alpine store 把 `$store.contactPanel.source` 同步进组件
3. UTM 首次落地时写入 session/cookie 做**首触归因**，提交时一并入库（否则访客跳几个页面后 UTM 就丢了）
4. `ContactMessageResource` 列表与详情展示来源与渠道，列表支持按来源筛选

安全：这些字段属于访客行为数据，权限沿用 `ContactMessagePolicy`；隐私政策页需相应说明收集范围。

#### A2 · 新询盘实时通知（1.5h）

现状：`ContactForm::submit()` 只写库，没有任何通知。营销站线索响应速度是转化的头号变量，现在只能靠人主动登后台刷。

要做：企业微信/钉钉群机器人 webhook + 邮件双通道，通知内容带上 A1 的来源与渠道。

**走队列异步发送，通知失败绝不能阻断表单提交**——访客侧的成功提示不依赖通知结果。

#### A3 · 统计代码注入位与转化事件（1h）

现状：全站没有任何 analytics 挂载点。想挂百度统计 / GA / 51.la 就得改两套主题的 `base.blade.php`。

要做：
1. **优先提供结构化字段**：`baidu_tongji_id`、`ga_measurement_id` 等，由固定模板生成代码，不给用户写脚本的机会

3. 表单提交成功时触发转化事件上报，供广告投放侧回传

> ⚠️ **安全说明**：自定义代码块等于给站点管理员一个在前台执行任意 JS 的能力，且**不能过 purifier**（会破坏脚本）。因此必须：

#### ✅ B2 · 分页 canonical 修正（已完成）

`seo-meta.blade.php` 改为保留 `page` 等区分内容的参数、只剥追踪参数，参数按键 `ksort` 后拼回，保证同一组参数不同顺序产生同一个 canonical。待剥参数清单放在 `config('filamentboot-site.seo.canonical_ignored_params')`（默认含 utm 五项、gclid、fbclid、msclkid、yclid、bd_vid、_bd_vid、spm），宿主接新渠道时追加即可。测试见 `tests/Feature/SiteSeoMetaTest.php` 三例。

<details>
<summary>原任务描述</summary>

**这是一个现存 SEO 缺陷。**

`resources/views/shared/components/seo-meta.blade.php:37` 用 `url()->current()`，该方法不含查询串。于是 `/solutions?page=2` 的 canonical 指向 `/solutions`，等于告诉搜索引擎第 2 页往后全是第 1 页的副本，列表页深层内容不会被索引。

列表页确实是分页的：`SiteFrontController.php:54,78,102` 三处 `paginate(12)`。

正确做法：**保留 `page` 参数、只剥 `utm_*` 之类追踪参数**，让每页都有自指的 canonical。

</details>

## 四、阶段 3 与阶段 4（未拆解）

### 阶段 3：企业站模块解耦 + 新闻模块（≈18h）

原规划的目录重构（≈10h）：

```
src/Cms/{Blocks,Filament,Models,Routing,Services,Themes}/
src/Modules/Corporate/{Cases,Products,Solutions}/
```

首页聚合从 `SiteFrontController::home()` 抽成模块提供的 `HomeSectionProvider`，通用控制器不再硬编码 `SiteCase::featured()`。路由 URL 与数据表名全部不变。

> ⚠️ **陷阱**：`BasePolicy` 从**短类名**推导权限点名。移动命名空间不影响推导，但顺手改类名（如 `SiteCase` → `CorporateCase`）会静默改掉权限点名并让现有角色权限失效。此阶段**只移动不改名**；确需改名必须在 Policy 显式覆盖权限前缀。

**新增：新闻/资讯模块（≈8h）**

这是营销型官网最大的单项功能缺口。现在只有案例/方案/产品三类「存量」内容，条数固定，sitemap 永远那几十条，搜索引擎抓取频次上不去，也没有素材做外链和公众号分发。营销站的 SEO 引擎是持续产出长尾落地页的资讯流。

**放阶段 3 而不是更早**，理由：阶段 3 本来就在重构目录结构，那时新建 `Modules/News/` 是顺手的事；现在做等于在还没定型的结构里再加一块，阶段 3 要搬两遍。

范围：文章模型 + 分类 + 列表/详情/归档 + 与阶段 2 的区块体系打通 + 进 sitemap + JSON-LD `Article`。

### 阶段 4：主题契约、缓存边界、包重命名与发布（≈14h）

沿用原规划，四块内容：

1. **主题契约**：`ThemeContract` + 每主题 `theme.php` manifest；主题切换前校验已发布页面用到的 template/block 是否被目标主题支持
2. **缓存边界**：面板骨架改纯 Alpine，Livewire 组件用 `<template x-if>` 延迟挂载，公开页响应头改 `public, max-age=...`（当前每个公开页都无条件 `@include` 含 `@livewire` 的 floating-contact，导致会话 Cookie + `Cache-Control: private, no-store`）
3. **包重命名** `filamentboot-site` → `filamentboot-cms`：与阶段 3 的目录重构合并为一次破坏性变更。**`plugins` 表数据迁移是必须的**——`PluginManager::syncFromInstalled()` 按 slug upsert，改名后会新建行并留下孤儿旧行，`is_enabled` 不会继承（阶段 1 期间已在本地 DB 实测确认此行为）
4. **发布**：干净的独立 Laravel 13 项目验证 `composer require`，v1.0.0
