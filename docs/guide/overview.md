# FilamentAdmin 项目概览

> 本文是面向公开发布的项目说明文档，用于 README、官网、安装文档和对外介绍引用。当前项目仍处于第一版开发阶段，文档中的“第一版目标”和“当前开发状态”必须分开维护。

## 项目定位

FilamentAdmin 是一个基于 Laravel 13 + Filament 5 的后台基础平台，主打两大特色：开箱即用的代码市场，以及组合最优的代码基座。

它的目标是让新项目不再重复搭建后台基础设施。第一版聚焦“可安装、可登录、可扩展、可开发业务模块”的后台 MVP；后续版本再逐步补齐在线升级、商业化插件市场、通知系统等增强能力。

### 开箱即用的代码市场

FilamentAdmin 对标 FastAdmin 多年沉淀的应用插件市场，但当前批准的路线不是 `Modules/` 双轨宿主模型，而是“基础包 + 插件市场包”的分层：

- `FilamentAdmin` 自身保持为后台基础包，负责后台基座、认证、权限、菜单、日志等通用能力。
- 插件市场作为另一个独立 Composer 基础包存在，并依赖 `FilamentAdmin`，负责本地扩展识别、状态管理、远程索引浏览和安装链路。
- 市场中纳管的对象分为 `系统基础依赖`、`普通插件`、`方案型插件`。方案型插件仍然是插件商品，只是安装后可能带来更多菜单、配置、初始化与数据准备流程。
- 来源层分为 `官方可信来源`、`官方收录来源`、`开源生态引用来源`。当前只有 `官方可信来源` 进入后台安装链路，其他来源先提供发现、兼容判断和安装指引。

第一版目标是先完成插件市场基础包、本地扩展清单、远程索引浏览、来源标记和官方可信来源安装链路；后续版本再补齐异步安装、在线升级、商业化插件市场、开发者入驻和平台分成等闭环能力。

### 组合最优的代码基座

FilamentAdmin 不追求重复造轮子，而是把 Laravel / Filament 生态中经过验证的扩展包按“开箱即用”的标准组合起来，并提供清晰的定制层与扩展点说明。

开发者拿到项目后，应该能通过文档快速知道：

- 项目用了哪些核心扩展包。
- 为什么选择这些包，而不是替代方案。
- 项目在 Laravel / Filament 默认行为上做了哪些定制。
- 二次开发时应该在哪一层扩展，哪些地方不要随意覆盖。

## 代码基座价值主张

### 透明可审计

项目不做黑盒封装。所有定制行为都应在架构文档中说明：改了哪个包的什么行为、为什么改、改在哪个文件、如何还原默认行为。

`composer.json` 中每一个非标准依赖，都应该能在文档里查到选型理由和替代方案对比。

### 组合最优而非碰运气

每个核心扩展点的选型遵循以下标准：

| 选型维度 | 硬性要求 |
|---------|---------|
| 下载量 | Packagist 累计下载量 >= 100 万，核心依赖 >= 1000 万 |
| 维护活跃度 | 近 6 个月有 commit，issue 平均响应 <= 30 天 |
| 文档完整度 | 官方 README 含完整安装、配置、进阶用法说明 |
| 生态兼容性 | 与 Filament 官方插件无已知冲突 |
| 团队背书 | 来自 Spatie、Filament 官方、Laravel 官方或著名社区维护者优先 |

不满足上述标准的方案不进入项目主体集成，可以作为可选插件或业务项目自选方案。

### 升级有路径

- 每个集成包都锁定主版本，patch/minor 版本可按兼容性自由升级。
- 集成包发布大版本时，项目在下一个主版本中跟进升级，升级前应公开升级评估。
- 任何依赖的破坏性变更都应在升级文档中给出迁移说明和代码示例。

### 能挖洞，也能填洞

项目应集中说明所有关键扩展点，包括 Trait、Contract、Event、ServiceProvider、Filament Resource、Page、Widget、Plugin 等。

如果业务方需要替换某个集成包，例如不用 Spatie Permission 改用 Bouncer，文档至少应说明替换工作量级别和主要改动范围。

## 代码基座默认集成清单

第一版目标是让开发者执行 `composer create-project filament-admin/skeleton` 后获得完整后台底座。下表区分“第一版目标”和“当前开发状态”，避免把后续阶段能力提前描述成已经落地。

| 能力域 | 第一版目标集成 | 目标默认行为 | 当前开发状态 |
|--------|---------------|-------------|-------------|
| 后台 UI 框架 | `filament/filament` | Panel Builder + Resources + Pages + Widgets | 已安装并配置 Admin Panel；一期后台基础管理 Resource 已落地 |
| 权限 | `spatie/laravel-permission` + `bezhansalleh/filament-shield` | Action 级别权限，自动生成权限点和管理 UI | 已接入并落地管理员、角色与权限、菜单规则、部门组织、数据权限的一期权限闭环 |
| 操作日志 | `spatie/laravel-activitylog` + `alizharb/filament-activity-log` | opt-in 模式，默认只记录后台关键操作 | 已集成；当前覆盖管理员、菜单、部门、数据权限等一期核心后台动作 |
| 媒体库 | `spatie/laravel-medialibrary` + `filament/spatie-laravel-media-library-plugin` | 本地磁盘存储，缩略图自动生成 | 未集成 |
| 系统配置 | `spatie/laravel-settings` + `filament/spatie-laravel-settings-plugin` | 强类型 PHP Settings 类 + Filament 配置页 + 缓存 | 未集成 |
| 插件市场 | `filament-admin/plugin-platform`（规划） | 独立 Composer 基础包，依赖 `FilamentAdmin`，承载扩展清单、来源标记、市场索引和插件生命周期管理 | 未集成 |
| API 认证 | `laravel/sanctum` | Bearer Token + Session 双模式 | 未安装，路由与统一响应规范未实现 |
| 登录限流 | Filament 5 内置能力 | 每分钟 5 次尝试 | 已通过登录测试覆盖 |
| 双因素认证 | `stephenjude/filament-two-factor-authentication` | TOTP + Recovery Code，默认关闭，管理员个人启用 | 已接入并有基础测试；完整 UI/恢复码流程需随阶段验收复核 |
| 测试与质量 | `pestphp/pest` + `larastan/larastan` + `laravel/pint` | 测试、静态分析、格式化检查 | 已配置；当前测试通过，CI 待完善 |

不进入默认集成清单的能力，应优先作为可选插件提供：

- 队列监控：如 `laravel/horizon`，仅 Redis 队列项目需要。
- 应用监控：如 `laravel/pulse`、`laravel/telescope`，开发期和生产期诉求不同。
- 数据库备份：如 `spatie/laravel-backup`，备份策略与部署方式强相关。
- 多语言：单语言项目无需默认引入完整本地化方案。
- 全文搜索：搜索能力通常和业务域强相关。
- 队列任务管理 UI：适合在第二版运维能力中作为可选增强。

主包只装“绝大多数后台项目都会用到”的基础能力；能让人犹豫一秒钟的依赖，一律优先放进可选插件。这是“开箱即用”和“主包不臃肿”的平衡点。

## 第一版功能规范

第一版不要一次性做成完整业务平台，而是先做“可安装、可登录、可扩展、可开发业务模块”的后台 MVP。

### 需求总纲

FilamentAdmin 希望沉淀一套对标 FastAdmin 的 Laravel + Filament 后台基础平台，重点提供后台系统的通用底座、权限体系、插件机制、快速开发规范和基础运维能力。

本项目主打开源生态，文档体系必须完备：安装记录、变更记录、定制说明都要清晰可查。核心是消除二次开发者的使用顾虑，让开发者能快速识别项目在 Laravel / Filament 默认行为基础上做了哪些定制。

### 对标 FastAdmin 默认能力

- 权限管理：管理员、角色/分组、菜单规则、权限节点、按钮权限、数据权限思路。
- 后台菜单：后台导航、菜单规则、权限绑定、控制器/页面入口管理。
- CRUD 快速开发：复用 Filament 官方 Artisan 命令生成 CRUD 骨架，后续沉淀项目规范模板。
- 插件中心：插件市场基础包提供系统基础依赖、普通插件、方案型插件的统一管理入口。
- 附件上传：图片、文件上传，默认本地存储，云存储能力以插件形式扩展。
- 会员/API 基础：第一版不做前台通用会员模块，但提供统一 API 响应、鉴权边界和路由规范作为业务模块底座。
- 多语言：第一版不做复杂多语言，只预留语言包和后台文案扩展方式。
- 操作体验：后台表格、筛选、排序、批量操作、导出、软删除/回收站、状态切换等通用管理体验。
- 开发辅助：命令行工具、静态资源发布、插件资源发布等开发效率能力；API 文档生成暂不纳入第一版。

### 具体功能清单

- 后台登录与账号管理：支持后台登录、退出、修改密码、管理员账号创建、禁用和基础资料维护。
- 角色与权限管理：支持角色划分、权限分配、菜单可见范围控制、操作权限控制，后续可扩展数据权限。
- 后台菜单管理：支持后台菜单、分组、图标、排序、权限绑定和插件菜单接入。
- 系统配置管理：支持站点级基础配置、上传配置、插件配置等统一配置入口，配置结果可缓存。
- 操作日志与登录日志：操作日志与登录日志分表存储，操作日志记录 Model 变更前后 diff，支持按保留天数清理。
- 附件与文件管理：支持图片、视频、附件等资源上传、分类、搜索、复用，第一版默认本地存储。
- 通用 CRUD 规范：沉淀 Model、Migration、Seeder、Policy、Filament Resource、Form、Table、Action、Filter、Infolist、Widget 的组织规范。
- 软删除与回收站：为常见后台资源提供软删除、恢复、彻底删除等通用管理能力。
- 数据导入导出：第一版先支持基础 Excel/CSV 导出，导入能力按业务模块逐步接入。
- API 基础能力：提供统一 API 返回结构、鉴权边界、错误格式和资源输出规范，后台 API 与业务 API 路由分离。
- 插件中心管理：支持查看系统基础依赖、已纳管插件、插件状态、版本、说明、依赖要求、配置入口和来源标记。
- 插件安装与启停：仅 `官方可信来源` 开放后台安装链路；`官方收录来源` 与 `开源生态引用来源` 先提供兼容信息、安装命令和文档指引。
- 插件配置管理：支持插件声明自己的配置项，并在 Filament 后台生成对应配置页面。
- 插件菜单与权限接入：支持插件向后台注册菜单、页面、资源、权限点和操作入口，并接入统一角色权限体系。
- 插件数据迁移与初始化：支持插件携带 Migration、Seeder、配置发布和资源发布能力；方案型插件允许在“已安装”后进入“待初始化”状态。
- 插件市场索引：第一版先支持读取本地或远程 JSON 索引，展示插件名称、分类、版本、作者、说明、兼容版本、来源标签、安装命令和文档链接。

### 第一版边界声明

- 第一版优先实现后台登录、管理员、角色权限、菜单管理、系统配置、操作日志、附件上传、软删除、基础导出、统一 API 规范、插件市场基础包、本地扩展清单、插件配置入口、插件状态与插件索引展示。
- 后台权限和前台用户权限必须分开设计，不要把管理员、运营、编辑、审核等后台角色，与前台用户登录、权益访问等业务权限混在一起。
- 扩展包只解决通用能力，不承担核心业务逻辑。
- 数据权限第一版先实现角色级范围控制，当前覆盖后台基础管理核心资源，不做字段级权限。
- 演示环境放到第二版规划，第一版不提供。
