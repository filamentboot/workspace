## 三、首批开发插件规划

以下按 FastAdmin 插件市场下载量与业务刚需程度排序，结合双轨制架构（工具型 `package` / 业务型 `module`）规划首批插件：

| 插件名称 | 类型 | 核心功能 | 开发优先级 | 备注 |
|----------|------|----------|-----------|------|
| **云存储 (OSS/S3)** | 工具型 | 替换本地存储，支持阿里云/腾讯云/AWS S3，自动缩略图生成 | P0 | 任何项目必装，走 `vendor/` Composer 包 |
| **短信发送** | 工具型 | 阿里云/腾讯云短信接口，支持验证码、通知模板、发送记录 | P0 | 登录验证/订单通知刚需，配置即用的 Settings 类 |
| **Excel 导入导出** | 工具型 | 复杂表格数据导出/导入，支持自定义模板、批量处理、进度提示 | P0 | 运营人员高频使用，基于 `maatwebsite/excel` 封装 |
| **第三方登录** | 工具型 | 微信/QQ/微博 OAuth 登录后台或前台会员，支持账号绑定 | P1 | 降低注册门槛，走 `laravel/socialite` 封装 |
| **支付模块** | 工具型 | 微信支付/支付宝集成，支持扫码/H5/JSAPI，订单回调与对账 | P1 | 电商/知识付费项目刚需，配置化路由与回调处理 |
| **富文本编辑器** | 工具型 | UEditor / TinyMCE / Tiptap 集成，自动适配 Media Library 图片上传 | P1 | 内容管理/公告发布必备，替代原生 textarea |
| **会员管理扩展** | 业务型 | 前台会员等级/积分/余额管理，消费记录与权益分配 | P2 | 解包至 `Modules/Member`，代码归项目所有，方便二开 |
| **数据回收站增强** | 业务型 | 全局软删除数据查看、对比、批量恢复与彻底清理 | P2 | 跨模块通用能力，可作独立工具包或轻量业务模块 |

### 插件开发原则
1. **工具型优先**：P0/P1 插件全部采用 `package` 模式，安装后配置即用，不侵入业务代码。
2. **配置驱动**：所有插件必须声明自己的 `Settings` 类，插件中心自动渲染配置页，避免重复开发设置界面。
3. **权限接入**：插件注册的路由/Resource 必须接入 Filament Shield 权限体系，不得绕过角色检查。
4. **文档配套**：每个插件需包含 `README.md`（安装/配置/升级指南）与基础 Pest 测试，符合上架品质门槛。

## 四、实现方案落地节奏

> 实施总原则：通用能力优先复用 Laravel / Filament 社区成熟方案，不重复造轮子；只有现有方案无法覆盖时才自研。

1. 使用 Laravel + Filament 创建 FilamentAdmin。Laravel 负责后台业务、数据模型、接口、权限、队列和邮件等服务端能力，Filament 负责快速搭建后台管理界面。
2. 先把 FilamentAdmin 定位成"后台基础平台"，不急着做官网、内容、运营这些业务模块，优先沉淀后台开发框架能力。
3. 补齐后台通用能力，包括后台登录、管理员、角色权限、菜单、系统配置、操作日志、附件上传、软删除、基础导入导出和统一 API 规范。
4. 沉淀通用 CRUD 开发规范，包括 Model、Migration、Seeder、Policy、Filament Resource、Form、Table、Action、Filter、Infolist、Widget 的组织方式。
5. 设计插件机制和插件中心。插件底层优先复用 Laravel Composer 包、Service Provider、Package Auto-Discovery、Migration、Config Publish 这些成熟机制；后台侧复用 Filament Plugin、Panel、Resource、Page、Widget 这些扩展点，不重新发明一套封闭插件系统。
6. 先实现插件中心 MVP，包括已安装插件列表、插件启停状态、插件配置入口、插件依赖说明、本地插件索引和远程插件索引读取。第一版不急着做在线购买、自动支付、复杂审核和完整云端分发。
7. 再补轻量定时任务、事件联动、队列任务和通知能力，让这套底座具备基础自动化能力，但先不在这一层把重队列和重异步系统做得太复杂。
8. 把这套项目整理成真正可以复制和复用的后台基础平台，作为项目二、项目三以及后续业务项目的共同起点。

## 五、第二版规划

### 5.1 定位

第一版完成"可安装、可登录、可扩展、可开发业务模块"的后台 MVP 之后，第二版目标是将 FilamentAdmin 从"能用"升级为"好用、好看、好维护"，并**完成代码市场的商业化闭环**——这是第一版预留、第二版兑现的核心承诺。

第二版重点：
1. **代码市场闭环**：异步安装、在线升级、商业化（开发者入驻、付费、License、分成）
2. **运维能力**：系统升级流水线、定时任务/队列可视化
3. **数据权限**：补齐第一版预留的行级数据过滤
4. **生态建设**：演示环境、官方云存储插件、通知系统

### 5.2 优先级排序

| 优先级 | 功能模块 | 理由 |
|--------|---------|------|
| 高 | 插件异步安装 + 在线升级 | 第一版最核心的体验缺口；代码市场闭环必需 |
| 高 | 插件商业化（开发者入驻 + 付费 + License + 分成）| 代码市场是两大核心特色之一，第二版必须形成完整闭环 |
| 高 | 数据权限体系 | 多部门项目的必要需求 |
| 高 | 系统升级流水线 | 第一版升级靠手动命令，体验断层最大；本项目定位"开箱即用"，升级也必须开箱即用（仅 Git 部署场景，其他场景做好引导） |
| 高 | 演示环境 | 开源生态建设，降低用户试用门槛 |
| 中 | 通知系统 | 提升系统可用性，站内通知优先 |
| 中 | 云存储官方插件 | 首批官方插件，验证插件机制（OSS / S3 / 七牛）|
| 中 | 定时任务 / 队列可视化 | 降低运维门槛 |
| 中 | API 文档生成 | 开发体验提升 |
| 低 | 多语言支持 | 国际化需求，视社区反馈决定优先级 |
| 低 | 安全增强 | 基础安全第一版已覆盖，高级场景按需补充 |

### 5.3 插件市场增强

#### 异步安装（队列 + 进程重载）

> **重要前置：进程重载需要部署侧配合**
>
> | 部署模式 | 是否支持自动 reload | 处理方式 |
> |---------|-------------------|---------|
> | 传统 PHP-FPM + Supervisor | 支持 | 项目提供 `filament-admin:reload` Artisan 命令调用预先在 `sudoers` 中授权的 `systemctl reload php-fpm`；安装任务完成后由队列 Worker 触发 |
> | Docker / Kubernetes | 不支持自动 reload | 安装完成后显示"请重启对应容器/Pod"提示，不尝试 `kill -USR2` 等花式重载 |
> | Laravel Octane / Swoole / FrankenPHP | 不支持自动 reload | 提示用户执行 `php artisan octane:reload`，并明确说明常驻进程模式下插件机制本身就需要重启 |
> | 共享主机 / 虚拟主机 | 不支持 | 第二版插件异步安装能力本就不适用此场景，UI 中检测到此环境时只提示"使用 Composer 命令安装" |
>
> 这一段约束必须在第二版安装界面用户操作前显式展示，避免用户期望落差。

- 用户在后台点击"安装"，推送安装任务到队列
- **工具型插件**：Worker 执行 `composer require vendor/plugin`，通过 `symfony/process` 调用系统级 Composer 二进制（非 Web 进程直接调用），完成后根据部署模式判断是否触发自动 reload
- **业务模块型插件**：Worker 下载 ZIP 包，解压到 `Modules/` 目录，执行 `composer dump-autoload`，更新 `modules_statuses.json`
- 安装进度通过 Livewire 实时推送到前端，显示安装日志
- 安装失败时回滚，记录错误日志并通知管理员

#### ZIP 包离线安装

- 支持后台上传插件 ZIP 包（适合无 SSH 访问、无法直接执行 Composer 的场景）
- **工具型插件 ZIP**：解压到临时目录，追加到 `composer.json` 的 `repositories` 配置（`path` 类型），执行 `composer require` 完成安装
- **业务模块型插件 ZIP**：直接解压到 `Modules/` 目录，执行 `composer dump-autoload`，代码归项目所有
- 适合私有插件、内网部署场景

#### 插件在线升级

- 后台自动对比已安装版本与市场最新版本
- 一键升级：推送升级任务到队列，执行 `composer update vendor/plugin`
- 升级前自动备份当前配置，升级后执行 `php artisan migrate`
- 升级历史记录，支持回滚到上一版本

#### 私有 Packagist / Satis 支持

- 支持配置私有插件源（企业内网部署场景）
- 允许企业发布内部插件到私有 Satis，通过市场索引分发给内部项目

### 5.4 系统升级能力

**后台版本检查**：
- 系统设置页展示当前 FilamentAdmin 版本
- 定期（或手动触发）检查 GitHub Release 是否有新版本，展示更新说明
- 区分小版本更新（可自动升级）和大版本更新（需手动参考升级文档）

**一键升级流水线（仅适用于 Git 部署场景）**：

> **适用边界**：本流水线假设服务器上有完整的 Git 工作目录且 PHP 进程有权限执行 `git pull` / `composer install`。以下场景**不适用**，需要走对应的部署侧升级流程：
> - **Docker 镜像部署**：升级 = 拉新镜像 + 重启容器，与本流水线无关
> - **Composer Artifact 部署**（CI 打包 zip 上传）：升级走 CI/CD 流水线
> - **共享主机 / 受限主机**：通常没有 SSH 和 git，只能手动 `composer update` 或上传文件
> - **Octane / Swoole 常驻进程**：升级后必须 `octane:reload`，本流水线最后追加这一步
>
> 后台升级 UI 在启动前自动探测部署环境（`.git/` 是否存在、`composer` 是否可执行、是否运行在 Octane 模式），无法满足前提条件时禁用一键升级按钮并提示原因。

基于 `salahhusa9/laravel-updater` 思路实现：
1. 开启维护模式（`php artisan down`）
2. Git 拉取最新代码
3. 执行 `composer install --no-dev`
4. 执行 `php artisan migrate --force`
5. 清理缓存（`config:cache`、`route:cache`、`view:cache`）
6. 如运行在 Octane 模式，追加 `php artisan octane:reload`
7. 关闭维护模式（`php artisan up`）

**升级文档规范**：每个大版本（SemVer 主版本号变更）必须更新 `docs/guide/upgrading.md`，文档内容：Breaking Changes 列表、需要执行的命令、配置变更项、废弃方法替代方案。

### 5.5 数据权限体系

**数据权限模型**：
- **全部数据**：可查看所有记录（超级管理员、管理员）
- **本部门数据**：只能查看本部门成员创建的记录
- **仅本人数据**：只能查看自己创建的记录
- 在角色上配置数据权限范围，叠加在操作权限（CRUD）之上

**实现方式**：
- 在 Resource 基类的 `scopeQuery()` 中根据当前用户角色的数据权限配置自动注入过滤条件
- 支持通过 `DataScope` Trait 快速为 Model 接入数据权限过滤
- 数据权限配置 UI 集成到角色管理页面

**部门/组织架构（可选）**：
- 如果业务涉及部门概念，提供轻量的部门树管理（无限极分类）
- 管理员可以绑定所属部门，作为数据权限过滤的依据

### 5.6 通知系统

**站内通知**：
- 基于 Laravel Notification + Filament 内置 DatabaseNotification
- 后台顶部通知铃铛，未读数徽章
- 通知列表：标题、摘要、时间、跳转链接、已读/未读状态
- 支持标记全部已读、清空通知

**邮件通知**：
- 复用 `MailSettings` 中的 SMTP 配置
- 提供通用邮件模板（可自定义 Logo、主题色）
- 支持后台触发"发送测试邮件"验证配置是否正确
- 关键系统事件（升级失败、插件安装失败、登录异常）自动发邮件给超级管理员

**短信/webhook 通知（插件形式）**：
- 短信通知以插件形式提供（阿里云短信插件、腾讯云短信插件）
- 支持 Webhook 通知：系统事件触发时向配置的 URL 推送 JSON 数据

**通知模板管理**：
- 后台可以编辑通知模板的文案（变量占位符支持）
- 区分系统级通知（不可关闭）和业务级通知（用户可选择是否接收）

### 5.7 定时任务与队列可视化

**定时任务管理**：
- 后台展示 `routes/console.php` 中注册的所有定时任务
- 显示任务名称、执行频率、上次执行时间、上次执行结果
- 支持手动触发单次执行
- 任务执行日志记录（成功/失败/耗时）

**队列监控**：
- 集成 `laravel/horizon`（Redis 队列）或展示基础队列状态
- 展示队列积压数、处理速度、失败任务列表
- 失败任务支持重试和删除
- 队列 Worker 运行状态监控

### 5.8 多语言支持

- 后台界面语言切换（中文/英文，管理员个人设置）
- 系统文案支持语言包覆盖（插件也可携带自己的语言包）
- 后台提供语言包管理页面（列出所有翻译 key，支持在线修改）
- 插件开发规范要求所有用户可见文案必须走翻译函数，不硬编码中文

### 5.9 附件云存储官方插件

- **阿里云 OSS 插件**（`filament-admin/oss-plugin`）：配置 AccessKey、Bucket、域名，medialibrary 自动切换到 OSS 磁盘
- **AWS S3 插件**（`filament-admin/s3-plugin`）：配置 Region、Bucket、AccessKey，标准 S3 协议兼容七牛、腾讯 COS 等
- 每个云存储插件包含：连接配置 UI、连接测试、迁移工具（本地文件批量上传到云端）

### 5.10 API 增强

**API 文档生成**：
- 集成 `knuckleswtf/scribe`，自动从路由和注释生成 API 文档
- 文档页面内置在后台（`/admin/api-docs`），需要管理员权限访问
- 支持在文档页面直接发起测试请求

**Webhook 支持**：
- 系统关键事件（用户注册、订单完成等）支持向外部系统推送 Webhook
- 后台配置 Webhook 订阅：URL、签名密钥、订阅事件类型
- Webhook 发送日志：成功/失败、响应码、重试记录

**API v2 路由**：
- 当有 Breaking Change 时启用 `/api/v2` 路由
- v1 路由继续维护一段时间（至少一个大版本周期），添加弃用警告响应头
- 提供 v1→v2 迁移指南

### 5.11 演示环境

- 提供在线 Demo 站，展示 FilamentAdmin 开箱即用的全部功能
- Demo 账号分级：超级管理员（只读）、管理员、运营、编辑、审核各一套
- Demo 数据定期重置（每天或每小时）
- Demo 环境禁用破坏性操作（删除、清空日志等）

### 5.12 安全增强

**文件上传安全**：
- 上传文件类型白名单校验（MIME 类型 + 扩展名双重校验）
- 上传文件大小限制（后台可配置）
- 图片文件二次渲染（防止图片马攻击）

**登录安全增强**：
- IP 登录白名单（超级管理员可配置允许登录的 IP 段）
- 异地登录提醒（与上次登录 IP 不同时发邮件通知）
- 登录设备记录（UA 解析，展示设备类型和浏览器）

**操作审计增强**：
- 关键操作（删除、权限变更、配置修改）要求二次确认（密码验证或 2FA 验证码）
- 审计日志不可删除（超级管理员也不行），只能归档

### 5.13 插件商业化（第二版正式启动）

> **定位说明**：插件代码市场是 FilamentAdmin 的两大核心特色之一。商业化是市场闭环的必经环节，因此从"第三版预研"提升为"**第二版正式启动**"。第一版目标是在插件表与市场索引中预留 `license` / `price` / `vendor_id` 等字段；若第一版插件中心未完整落地，第二版需要先补齐这些字段与迁移，再启动商业化闭环。

**开发者生态建设**：
- **插件开发者入驻流程**：GitHub OAuth 登录 + 实名认证；提交包名、所属组织、收款信息
- **官方审核机制**：
  - 自动化：CI 跑 Pest 测试 + Larastan level 5 + composer audit + 危险函数扫描
  - 人工：核对包名是否冲突、`composer.json` 元数据合规性、README 完整性、首版人工复核代码
- **插件上架标准**：必须遵循第一版定义的"插件开发品质门槛"，且通过自动+人工双审核
- **开发者评级**：根据插件下载量、好评率、issue 响应速度形成开发者信用分，影响后续上架速度

**付费插件机制**：
- **定价模式**：免费 / 一次性买断 / 按年订阅
- **授权校验**：License Key 机制
  - 安装时填入 Key，插件 ServiceProvider boot 时向官方授权服务器验证
  - 允许 7-30 天离线缓存，断网不影响使用
  - 校验失败时插件进入"只读"模式，不影响主项目运行
- **退款政策**：买断插件 7 天无理由退款（首次购买，每个账号每个插件限一次）
- **分成结算**：
  - 平台抽成比例：**初定 5%**（远低于 App Store 30%），目的是早期最大化吸引开发者入驻；后续根据平台成本与生态成熟度可上调，调整需提前 90 天公告，已上架插件按签订时的费率执行历史订单
  - 结算周期：月结，T+15
  - 提现方式：支付宝 / 微信 / 对公账户

**分发机制**：
- **免费插件**：走 Packagist 公开分发，市场仅提供索引和元数据
- **付费插件**：走官方私有 Packagist（基于 Satis 自建），用户购买后获得授权访问 token
- **版本管理**：插件支持多版本并存（按 FilamentAdmin 主版本锁定兼容范围）；用户购买后可下载所有兼容当前 FilamentAdmin 主版本的更新

**法律与合规**（第二版必须配齐，否则不能上线收款）：
- 用户协议：明确"代码归买家所有 + 可二开 + 不可二次分发"
- 开发者协议：明确"提交即授权平台分发 + 收入分成约定 + 内容合规要求"
- 备案：根据团队所在地决定 ICP 备案、增值电信业务许可证（如需要）

## 附录：后台 UI 调整参考

Filament 官方没有类似 WordPress 那样"一键换肤"的主题包，社区里也没有能把 Filament 变成"Layui/Element UI 风格"的成熟国产主题包。这主要是由技术栈决定的：Filament 基于 Tailwind CSS，它的设计理念是"配置化定制"（改颜色、字体、圆角），而不是"替换模板"。

### 审美差异

国人习惯的后台（如 Layui、Vue Element Admin、FastAdmin）通常是 Bootstrap 风格：边框明显、信息密度高、按钮多、色彩重（深蓝/深黑侧边栏）。Filament 风格是典型的欧美 SaaS 风格：极简、大留白、圆角大、默认是浅色侧边栏（虽然可以改深色）、信息密度较低。

### 现有美化相关包

| 包名 | 功能 | 评价 |
|------|------|------|
| `hasnayeen/themes` | 提供侧边栏颜色切换、深色模式切换、布局调整 | 最常用。可以让侧边栏变黑/变蓝，增加一点"传统后台"的感觉 |
| `filament/filament` (自带) | 官方支持自定义 Brand Logo、Favicon、Colors、Font | 必须用。把主色调改成国人喜欢的"阿里蓝"或"微信绿"，字体改成微软雅黑 |
| `swisnl/filament-backgrounds` | 登录页背景图/粒子效果 | 仅美化登录页，让登录看起来不那么素 |

### 贴合国人习惯的调整建议

1. **修改侧边栏为深色（最重要）**：国人后台 90% 是深色侧边栏。Filament 5 支持得很好，在 AdminPanelProvider 中配置 `->darkMode()`、`->sidebarCollapsibleOnDesktop()` 等。
2. **调整主色调**：默认是蓝色，但可以改成更符合国内审美的颜色（通过 Tailwind 配置）。
3. **增加信息密度**：Filament 表格默认行高较大，可以通过自定义 CSS 稍微压缩行高，让一屏显示更多数据。
4. **替换特定组件**：富文本集成 tiptap-editor（Filament 官方推荐）；省市区级联使用 `filament-china-region` 之类的第三方包。

> 建议：不要试图把 Filament 改成 Layui 的样子，那是跟 Tailwind 的底层逻辑对抗。花半天时间把侧边栏改成深色、换上项目 Logo、调好主色调，它看起来就会像一个成熟的商业产品了。
