# FilamentAdmin
## 需求：
希望沉淀一套对标 FastAdmin 开发体验的 Laravel + Filament 后台基础平台。专注提供后台系统的通用底座、权限体系、插件机制、快速开发规范和基础运维能力。

具体需求如下：
- 后台能力要像 FastAdmin 一样开箱即用，但技术栈换成 Laravel + Filament，尽量复用 Laravel 生态和 Filament 扩展机制。这一点非常重要。
- 作为后续所有业务项目的后台开发底座，优先解决“快速搭后台、快速接业务、快速扩展插件”的问题。
- 默认安装后就具备后台登录、管理员、角色权限、菜单、系统配置、操作日志、附件上传、插件中心等通用能力。
- 支持开发者通过 Laravel Model、Migration、Seeder、Policy、Filament Resource 快速新增业务模块。
- 支持多角色协作，至少满足超级管理员、管理员、运营、编辑、审核等角色的权限分配基础。
- 插件市场是FilamentAdmin的长期核心能力之一，用于沉淀行业模块、运营模块、主题模块、集成模块和业务扩展模块，让后续项目可以通过安装插件快速获得能力。
- 插件市场第一阶段不追求完整商业化闭环，先实现本地插件中心、插件启停、插件配置、插件依赖、版本信息和安装说明，后续再扩展远程市场、审核、付费、升级和分发机制。

## 对标 FastAdmin 默认能力：

FastAdmin 默认安装后，本质上是一套“后台快速开发框架”，核心不是官网 CMS，而是后台底座和扩展生态。本项目应优先对标这些能力。

- 权限管理：管理员、角色/分组、菜单规则、权限节点、按钮权限、数据权限思路。
- 后台菜单：后台导航、菜单规则、权限绑定、控制器/页面入口管理。
- CRUD 快速开发：根据数据表或资源快速生成控制器、模型、视图、JS、语言包、菜单、回收站等能力。
- 插件中心：插件安装、卸载、启用、禁用、升级、配置和扩展入口。
- 附件上传：图片、文件上传，后续可扩展云存储、大文件上传、分片上传。
- 会员/API 基础：FastAdmin 有通用会员模块和 API 模块；本项目只做后台权限模块，后台管理员模块， 不做前台通用会员和API模块
- 多语言：FastAdmin 支持多语言；FilamentAdmin第一版先不做复杂多语言，只预留语言包和后台文案扩展方式。
- 操作体验：后台表格、筛选、排序、批量操作、导入导出、软删除/回收站、状态切换等通用管理体验。
- 开发辅助：API 文档生成、命令行工具、静态资源发布、插件资源发布等开发效率能力。

## 具体功能：

- 后台登录与账号管理：支持后台登录、退出、修改密码、管理员账号创建、禁用和基础资料维护。
- 角色与权限管理：支持角色划分、权限分配、菜单可见范围控制、操作权限控制，后续可扩展数据权限。
- 后台菜单管理：支持后台菜单、分组、图标、排序、权限绑定和插件菜单接入。
- 系统配置管理：支持站点级基础配置、上传配置、邮件配置、短信配置、插件配置等统一配置入口。
- 操作日志与登录日志：记录后台关键操作、登录记录、异常行为，便于审计和排查问题。
- 附件与文件管理：支持图片、视频、附件等资源上传、分类、搜索、复用，第一版先做后台通用附件能力。
- 通用 CRUD 规范：沉淀 Laravel Model、Migration、Seeder、Policy、Filament Resource、Form、Table 的开发规范，让后续业务模块可以快速复制。
- 软删除与回收站：为常见后台资源提供软删除、恢复、彻底删除等通用管理能力。
- 数据导入导出：第一版可以先支持基础 Excel/CSV 导出，导入能力按业务模块逐步接入。
- API 基础能力：提供统一 API 返回结构、鉴权边界、错误格式和资源输出规范，方便项目二、项目三读取数据。
- 插件中心管理：支持在后台查看已安装插件、插件状态、插件版本、插件说明、依赖要求、配置入口和启停状态。
- 插件安装与启停：支持通过 Composer 包或本地插件目录安装插件，后台可以启用、停用和查看插件运行状态。
- 插件配置管理：支持插件声明自己的配置项，并在 Filament 后台生成对应配置页面，避免每个插件都重复开发设置页。
- 插件菜单与权限接入：支持插件向后台注册菜单、页面、资源、权限点和操作入口，并能接入统一角色权限体系。
- 插件数据迁移与初始化：支持插件携带 Migration、Seeder、配置发布和资源发布能力，安装后可以完成必要的数据表和初始数据准备。
- 插件市场索引：第一阶段先支持读取本地或远程 JSON 索引，展示插件名称、分类、版本、作者、说明、兼容版本、安装命令和文档链接，为后续真正的市场化分发预留空间。

## 实现方案 / 落地清单：
需要的功能优先找开源市场的成熟方案，尽量不自己写功能。 


1. 第一步，使用 Laravel + Filament 创建FilamentAdmin。Laravel 负责后台业务、数据模型、接口、权限、队列和邮件等服务端能力，Filament 负责快速搭建后台管理界面。
2. 第二步，先把FilamentAdmin定位成“后台基础平台”，不急着做官网、内容、运营这些业务模块，优先沉淀后台开发框架能力。
3. 第三步，补齐后台通用能力，包括后台登录、管理员、角色权限、菜单、系统配置、操作日志、附件上传、软删除、基础导入导出和统一 API 规范。
4. 第四步，沉淀通用 CRUD 开发规范，包括 Model、Migration、Seeder、Policy、Filament Resource、Form、Table、Action、Filter、Infolist、Widget 的组织方式。
5. 第五步，设计插件机制和插件中心。插件底层优先复用 Laravel Composer 包、Service Provider、Package Auto-Discovery、Migration、Config Publish 这些成熟机制；后台侧复用 Filament Plugin、Panel、Resource、Page、Widget 这些扩展点，不重新发明一套封闭插件系统。
6. 第六步，先实现插件中心 MVP，包括已安装插件列表、插件启停状态、插件配置入口、插件依赖说明、本地插件索引和远程插件索引读取。第一版不急着做在线购买、自动支付、复杂审核和完整云端分发。
7. 第七步，再补轻量定时任务、事件联动、队列任务和通知能力，让这套底座具备基础自动化能力，但先不在这一层把重队列和重异步系统做得太复杂。
8. 第八步，把这套项目整理成真正可以复制和复用的后台基础平台，作为项目二、项目三以及后续业务项目的共同起点。
9. 至此，本项目完成。

## FilamentAdmin插件市场设计：

插件市场不是从零造一个和 Laravel 生态割裂的系统，而是站在 Laravel 和 Filament 的成熟扩展机制上做产品化封装。

- 插件形态：优先采用标准 Composer Package，每个插件通过 Laravel Service Provider 注册服务、路由、配置、迁移、事件和前后台能力。
- 后台接入：插件如果需要后台界面，应通过 Filament Plugin、Resource、Page、Widget、Navigation Item 接入统一后台，而不是单独做一套管理端。
- 安装方式：第一阶段以 Composer 安装和本地插件目录为主，后台负责展示、配置、启停和状态检查，不强行在后台直接执行高风险安装命令。
- 市场索引：第一阶段可以用一个远程 JSON 或私有 Packagist / Satis 索引来描述插件列表，包含插件名、包名、版本、分类、作者、说明、兼容版本、安装命令、文档地址和截图。
- 启停机制：插件启停不要依赖删除代码，而是通过数据库配置或配置文件控制功能是否注册菜单、路由、事件监听和定时任务。
- 权限接入：插件必须声明自己的权限点，并接入统一角色权限体系，避免插件装上后绕过后台权限控制。
- 数据迁移：插件可以携带 Migration 和 Seeder，但安装、升级、回滚必须有明确记录，避免插件破坏主系统数据。
- 版本兼容：插件需要声明支持的 Laravel、Filament、PHP 和项目底座版本，避免后续升级时出现隐性冲突。
- 安全边界：远程市场第一阶段只展示和引导安装，不直接执行未知远程代码；真正开放第三方插件前，需要补审核、签名、来源校验和权限声明。
- 商业化边界：付费插件、授权校验、开发者入驻、分成结算、在线升级属于二期或三期，不进入FilamentAdmin第一版 MVP。

## FilamentAdmin第一版边界：

第一版不要一次性做成完整业务平台，而是先做“可安装、可登录、可扩展、可开发业务模块”的后台 MVP。

- 第一版优先实现：后台登录、管理员、角色权限、菜单管理、系统配置、操作日志、附件上传、软删除、基础导出、统一 API 规范、本地插件中心、插件配置入口、插件启停状态、插件索引展示。

- 后台权限要区分两类：一类是 Laravel / Filament 后台管理员、运营、编辑、审核等角色权限；另一类是前台用户登录、访问受限内容、查看权益这类前台用户权限。两套权限不要混在一起设计。
- 扩展包只解决通用能力，不承担核心业务逻辑。权限、媒体库、上传、富文本编辑器可以优先用成熟 Laravel / Filament 扩展；
